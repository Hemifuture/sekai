# 海岸响应续接：局部凝结因果补证

基线：`77957db`。续接产品收口计划第 2 项，仅补既有生产算子的受控证据。
独立工作区由宿主管理；主目录候选保持可运行。

## 范围与任务

- [x] 使用六格 C2 状态，固定温湿度、地形梯度和下层风，反转上层风，
  直接调用生产 `apply_moisture`；迎坡有地形凝结、背坡无地形凝结。
- [x] 同一夹具将地形梯度置零，证明响应来自地形；检查凝结对可用水汽的消耗方向。
- [x] 定向 Release 测试、格式与 Clippy；记录结果和未覆盖范围。
- [x] UI 接入核查：已有站点月表的地形降水占比继续读取发布终态；本轮不改生产结果，
  不扩大 Draft 实验支持域，不把局部凝结证据写成完整雨影或用户 UI 验收通过。

六格是局部源项所需的最小现有立方球网格，不生成新世界，不跑周期求解。
温度、风速与梯度是受控夹具输入，不是生产默认值或新验收包络；生产函数计算凝结，
测试不复制公式。原有物理助手测试只覆盖公式，不能捕获 C2 误用下层风的接线回归。
不新增生产 API、依赖、阈值或身份版本；如果发现生产缺陷，另行修订范围与身份。
编译单进程 `-j 2`、测试单线程，一次命令限 600 秒；不启动网络或 UDP 探针。

## 续接调查与 UI 检查

生产质量算子 `orographic_neighbor_response_from_fields` 根据上层风选择山脊两侧邻格，
比较已有降水；这属于终态统计，不能单独证明地形造成下游干燥。
`LayeredTendencySystem::apply_moisture` 才执行越岭风与梯度点乘、LCL 判定和水汽扣账。
因此本轮选择直接验证这一层，不再生成一个只重复统计指标的世界。

UI 消费路径为 `generators/natural/site_climatology.rs` 对发布字段的面积取样，
再由 `app/site_climatology.rs` 月表显示降水和地形降水占比。没有新增显示算法。
用户可在主目录 `cargo run --release --bin sekai`，草稿/程序化海岸/种子42/目标陆比25%，
生成后打开站点月表，检查降水、地形降水占比及越岭风；零地形降水本身不等于错误，
需结合风向、水汽与 LCL。用户验收以及完整海陆/山脉/海峡因果响应仍未完成。

## 实测结果

新增 `orographic_moisture_response_follows_upper_wind_and_requires_terrain` 首次执行即通过：
迎坡地形凝结为正，反向越岭风和零梯度两个对照为零；迎坡的总降水高于平地，
水汽倾向低于平地。下层风始终保持与迎坡上层风相反，因而测试可以区分风层接线。
这是对既有行为的特征测试，不是修复后才变绿的缺陷回归；没有修改生产实现。

Release 单测 1 passed，随后同源项模块 45 passed / 1 ignored（原有离线角动量探针），
执行耗时 0.02 秒；初次编译 2 分 38 秒。严格 workspace/all-targets/all-features
Clippy、WASM all-features lib check、fmt 与 diff 检查通过。未重跑完整世界或新增 seed/profile。
只有 `cfg(test)` 内容改变，不改变产物身份，也不需要重建 native/Trunk 发布产物。

下一证据是带输送的迎风/背风受控对照及当前工作域原生动量/强迫定位；本轮局部源项
不能排除输送、月平均或重采样造成的偏差，产品收口计划第 2 项保持未完成。

## 每项承重技术的出处

- C2 越岭风选择：既有 P4 陆地蒸散规格第 4 节、生产注释的 Sheppard (1956)
  与 Hunt & Snyder (1980)；本轮只验证既有接线，不提出新的层间近似。
- 凝结与 LCL：生产 `lcl_adjusted_orographic_condensation_kg_m2_s` 及已有解析极限测试。
- 完整雨影和支持域仍以海岸响应计划及冻结海岸规格为准，局部源项不证明下游输送。
