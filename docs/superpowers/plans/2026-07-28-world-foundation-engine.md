# World Foundation and Generation Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Sekai's deterministic, UI-independent world foundation: typed IDs and units, validated world specifications, extension-field contracts, a finite planar spatial snapshot, typed generation stages, caching, diagnostics, and a reproducible spatial build.

**Architecture:** New `world` modules own immutable data contracts, `engine` owns generic orchestration, and `generators::spatial` owns the first real generator. Stages receive only typed input bundles; type erasure exists solely inside the scheduler. This plan deliberately delivers a validated `SpatialSnapshot` and `BuildReport`, not an empty `WorldSnapshot`; the final snapshot is introduced only after natural, magic, and society sections have real contracts.

**Tech Stack:** Rust 2021, MSRV 1.85, serde, serde_json 1.x, thiserror 2.x, blake3 1.8.x, rand 0.9, rand_chacha 0.9, delaunator 1.x, native and `wasm32-unknown-unknown`.

**Web Bundle Tool:** Trunk 0.21.14, pinned to the [official release](https://github.com/trunk-rs/trunk/releases/tag/v0.21.14) for the local acceptance gate.

**Design Source:** `docs/superpowers/specs/2026-07-28-sekai-current-slice-world-design.md`

## Global Constraints

- Keep the existing single-package layout; do not create workspace crates in this plan.
- `src/world/**` must not import egui, eframe, wgpu, UI resources, renderers, or generation algorithms.
- `src/engine/**` must not contain geology, climate, magic, settlement, or rendering policy.
- New spatial generation must use `delaunator` through core `WorldPoint` values; it must not expose egui coordinates.
- Do not modify the existing app, terrain pipeline, renderers, or `MapSystem` except for the one baseline Clippy fix in Task 1.
- Do not add history years, events, timelines, or placeholder domain sections.
- Do not publish a `WorldSnapshot` with optional or empty natural, magic, or society sections.
- Do not introduce `unsafe` code in `world`, `engine`, or the new spatial generator.
- Every serialized map or registry uses deterministic ordering (`BTreeMap` / sorted vectors), never `HashMap`.
- The same inputs and algorithm versions must yield the same IDs, topology, hashes, and stage order.
- Execute stages sequentially in this subsystem; parallel scheduling is a later optimization that must preserve the same graph order and reports.
- All public types and error variants require concise rustdoc.
- Follow TDD: observe each new test fail for the stated reason before adding implementation.
- Every task ends with its focused tests, formatting, Clippy for touched targets, and a commit.

`PlanarSpaceSpec::validate` must reject dimensions outside `1..=100_000_000 m`, aspect ratios outside `1.0 / 16.0..=16.0`, and cell counts outside `16..=200_000`. - [ ] **Step 6: Implement versioned seed derivation**

`StageIdentity` contains `id: &'static str`, `version: u32`, and `namespace: &'static str`. `derive_stage_seed` hashes this exact byte framing:

```text
"sekai-stage-seed-v1\0"
root seed as little-endian u64
namespace length as little-endian u64
namespace UTF-8
stage ID length as little-endian u64
stage ID UTF-8
stage version as little-endian u32
```

`derive_entity_seed` hashes:

```text
"sekai-entity-seed-v1\0"
32 stage-seed bytes
entity namespace length as little-endian u64
entity namespace UTF-8
entity key as little-endian u64
```

Its signature requires the entity namespace explicitly:

```rust
pub fn derive_entity_seed(
    stage_seed: StageSeed,
    entity_namespace: &str,
    entity_key: u64,
) -> StageSeed;
```

Use stable namespaces such as `cell`, `species`, `culture`, `settlement`, and `polity`; rule packs use their registered namespace. This prevents equal raw values from different ID types from sharing a stream.

Use BLAKE3 and retain all 32 output bytes:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct StageSeed([u8; 32]);

pub struct StageRng(rand_chacha::ChaCha8Rng);

impl StageRng {
    pub fn from_seed(seed: StageSeed) -> Self {
        use rand::SeedableRng;
        Self(rand_chacha::ChaCha8Rng::from_seed(seed.into_bytes()))
    }
}

impl rand::RngCore for StageRng {
    fn next_u32(&mut self) -> u32 {
        self.0.next_u32()
    }

    fn next_u64(&mut self) -> u64 {
        self.0.next_u64()
    }

    fn fill_bytes(&mut self, dest: &mut [u8]) {
        self.0.fill_bytes(dest);
    }
}
```

Expose the byte array through `StageSeed::into_bytes`; do not expose `ChaCha8Rng`.

- [ ] **Step 3: Implement deterministic jittered sites**

`PlanarVoronoiBuilder::build` must call `PlanarSpaceSpec::validate` before allocating sites. `JitteredGridSites::generate` receives only an already validated space and must:

1. compute `columns = ceil(sqrt(target_cells × aspect_ratio))`;
2. compute `rows = ceil(target_cells / columns)`;
3. emit one site per grid slot in y-major then x-major order;
4. draw independent x/y jitter in `[-0.45, 0.45]` cell widths;
5. keep sites strictly inside their slots using a `1e-9` normalized inset;
6. return `columns × rows` sites and never call a global RNG.

The target count is approximate by design; the generated count must be at least the request and less than request plus one full row.

- [ ] **Step 4: Implement rectangle-clipped Voronoi polygons**

Use `delaunator::triangulate` only to find candidate neighboring sites. For each site:

1. start with the rectangle polygon;
2. sort and deduplicate Delaunay neighbors;
3. clip the polygon against each neighbor's perpendicular-bisector half-plane using Sutherland–Hodgman;
4. remove consecutive vertices closer than `1e-12 × max_dimension`;
5. enforce counter-clockwise winding;
6. rotate vertices so the lexicographically smallest quantized point comes first;
7. compute area and centroid with the shoelace formula.

The kept half-plane for site `s` against neighbor `n` is:

```text
2 × point · (n - s) <= n · n - s · s
```

Reject empty, non-finite, or near-zero polygons with `SpatialBuildError`.

- [ ] **Step 5: Reconstruct shared and boundary edges**

For every polygon segment:

1. quantize endpoints using `epsilon = max(width, height) × 1e-9`;
2. canonicalize endpoint order;
3. insert the canonical segment key into a `BTreeMap`;
4. one owning cell creates a boundary edge;
5. two owning cells create an internal edge;
6. more than two owners is an error;
7. sort canonical edge keys before assigning contiguous `EdgeId` values;
8. derive sorted cell neighbors only from two-owner edges.

This edge table is authoritative; do not preserve a second Delaunay-neighbor truth.

- [ ] **Step 3: Implement cache keys and in-memory values**

Compute `StageCacheKey` from this framed input:

```text
"sekai-stage-cache-v1\0"
stage namespace length as little-endian u32, then UTF-8 bytes
stage ID length as little-endian u32, then UTF-8 bytes
stage version as little-endian u32
output artifact-key length as little-endian u32, then UTF-8 bytes

    artifact-key length as little-endian u32, then UTF-8 bytes
    32 artifact content-hash bytes
```

`MemoryStageCache` stores the output artifact and output hash under the cache key. Values are process-local `Arc` instances; disk persistence is out of scope. `new()` uses a 32-entry cap, `with_max_entries` rejects zero, and insertion beyond the cap evicts the oldest inserted key using a deterministic FIFO queue. Cache capacity changes performance and reports only, never artifact content.

- [ ] **Step 4: Implement external artifacts**

`ExternalArtifacts::insert<T: Artifact>` validates the value, computes and stores the same stable content hash used for stage outputs. Invalid values, duplicate keys, and type mismatches are errors.

- [ ] **Step 5: Implement atomic scheduling**

For each graph stage:

1. load only declared input hashes;
2. derive the stage seed from the explicit `RootSeed` supplied to `BuildEngine::build`;
3. compute the cache key;
4. on a hit, insert the cached output and record a cache hit;
5. on a miss, load typed inputs, run the stage, call output artifact validation, stream-hash its serialization, and cache it only after both checks pass;
6. append `StageReport` in deterministic graph order.

On success, compute `BuildReport.result_hash` with BLAKE3 over the domain prefix `sekai-build-result-v1\0` followed by each produced artifact key and 32-byte content hash in graph order, using length framing for keys. External inputs influence the result through declared stage outputs and are not copied into this result frame.

```rust
    cache: &mut MemoryStageCache,
) -> Result<BuildOutcome, BuildFailure>;
```

It returns `BuildOutcome { artifacts, report }` only if all stages finish. On error, return `BuildFailure { report }`; do not expose the partial artifact store.
