## 已实现的作者闭环

作者输入归一个校验后的配方事务管理。临时控件文本与已确认输入分开；确认合法变化才进入撤销历史、递增修订并使旧构建请求失效；不变值不制造命令。撤销重做恢复输入，不承诺立即恢复对应世界。普通编辑、撤销重做均需显式重建。

后台构建遵循请求／项目 epoch／输入 revision／RecipeId 身份。旧有效世界在生成、取消、失败及陈旧结果期间保留；候选显示资源准备完成后才原子发布。同一完整 worker 真正结束并 join 前不释放构建槽，取消不是立即启动第二个 worker 的许可。失效的细节任务也不能污染新发布世界。

项目文件采用严格的 V1 配方格式，记录生成管线、阶段版本、质量档位计划、固定模型／规则／依赖内容身份和浮点平台信号，另含有限视图偏好。文件中**没有世界、阶段缓存、历史世界、网格或求解轨迹快照**；撤销历史不跨会话保存。运行内存中保留旧有效世界是失败恢复，不是持久快照。

兼容文件打开后自动生成一次；所以保存重开**不能立即恢复地图**，必须等待现算。旧算法或依赖身份不兼容时不会悄悄按新版重建；保留原文件，明确列出差异，只有显式选择升级副本后才按当前身份生成并另存。未知格式或科学 schema 明确拒绝。只有浮点平台信号不同也需要明确确认；信号一致不构成跨平台逐位再现的保证。

保存通过后台 IO 和 Windows 原子替换／备份恢复完成，处理晚到保存、外部文件改变、路径别名、占用失败及升级副本覆盖源文件的风险；确认保存的仅是其捕获的配方身份。未保存的临时文本和草稿、已保存身份、当前已发布世界、待重建状态在 UI 中分开反馈。

生成计时、取消反馈、IO、显示资源准备和帧间隔观测已经接通。UI 现在显示当前请求的真实地表准备／自然世界构建／显示准备粗阶段，关闭性能观测也有效；阶段和拒绝输入均不进入项目文件。实际 `ClimateWorkDomainStage + bundled CausalNaturalFormationStage(P2–P5)` 不提供独立细粒度／空间局部重算。原生 desktop 为主要交付，wasm 库兼容检查不等于浏览器异步功能验收。
