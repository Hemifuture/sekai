## 4. 作者输入、命令与身份

### 4.1 输入事实源

概念上的 AuthorInputs 聚合当前 root seed、pipeline、quality profile、球面空间及现有 Formation/Tectonic/Relief/Geologic 等实际生成输入。复用领域类型、默认值和校验器，不复制科学常量。

现有 UI 中所有影响生成的控件均经同一输入事务入口，包括 seed、预设、profile 和预设联动。相机、投影、字段选择、色板不进入生成历史。

沿用 SeaLevelPolicy：水量模式以作者水量为输入、陆比为结果；目标陆比模式以陆比为输入、报告反推水量。非活动输入保留供切回，不能用上次实测值覆盖作者值，不承诺两个独立目标总能同时满足。建议将驱动标签明确为“水量驱动/目标陆比驱动”，属于文案澄清，不改变物理机制。

### 4.2 最小命令

使用具体输入变更事务：标签、before、after、会话序号。小参数快照保证预设联动完整；不存世界数组，不做持久事件溯源。

- 拖动只在松手/确认时提交一次；键盘明确提交形成一次事务；no-op 不入栈。
- 预设的所有联动字段为一条命令。
- 新 seed 记录具体值；redo 复用该值，不重新随机。
- 无效控件文本保留错误反馈，不提交；Escape 放弃尚未提交编辑。
- 新命令清除 redo 分支；生成、取消、发布、保存不是输入命令。
- 编辑未提交时不得显示新输入已经保存或已经生成。

### 4.3 身份与版本

分开维护：

1. 作者输入身份：有版本的规范编码，包含保存的非活动输入；用于历史和磁盘比较。
2. 构建身份：有效生成输入、seed、pipeline/stage 语义版本、规则和依赖内容哈希、profile/拓扑/分辨率及数值策略版本；复用 engine 指纹链。
3. 请求身份：会话 epoch + build ID + 捕获 revision。open/new 切换 epoch，防止跨项目晚到结果。

规范编码要求数值无损往返、有限值、稳定字段/映射顺序以及明确负零处理；不对任意 JSON 文本直接 hash。文件路径、时间戳、UI 状态、请求序号不替代生成内容身份。

app 版本/commit 仅作诊断，不能替代生成身份。Draft 名称本身不固定精度：若档位定义、分辨率或数值策略改变，必须反映在生成身份中。精确浮点复现另受审计平台约束。

## 5. 会话状态与界面反馈

用相互独立的事实表达状态：

- Draft：最近已提交、通过输入校验的配方。
- Published：可空，仅内存中的有效世界、来源输入/身份、显示资源与报告。
- Build：Idle / Running / Cancelling / ReadyToCommit。
- Save：路径、成功保存的配方内容身份、正在保存的捕获身份。
- Error：归属于具体项目/请求的失败说明，不伪装成新世界。

固定显示草稿与当前地图来源；不一致时提示“参数已修改，地图仍为上次有效结果”。未保存、待重建、正在构建分别显示。已保存但没生成是合法状态。

首次打开配方完成解析后、构建完成前显示明确空状态，不拿其他项目或示例图冒充结果。运行中编辑当前项目时，旧有效世界仍可浏览。

| 事件 | 草稿 | 地图 | 请求 |
| --- | --- | --- | --- |
| 合法编辑/undo/redo | 更新 | 保留旧图并标明 | 在途请求失效并取消 |
| 点击重建 | 捕获输入 | 保留旧图 | 启动一次 |
| 打开兼容项目 | 恢复输入 | 新项目暂时无图 | 推荐自动启动一次 |
| 取消/失败 | 保留 | 保留当前项目旧有效图；首次仍为空 | 结束并给重试入口 |
| 候选陈旧 | 不变 | 不变 | 丢弃，不报发布成功 |
| 新鲜候选完整就绪 | 不变 | 原子替换 | 完成 |

视图设置是非科学偏好；可随手动保存写入小型项目元数据，但不属于生成配方/身份。不因每次相机运动反复弹未保存提醒，不能让视图偏好成为第二套科学状态。

## 6. 重开现算的推荐交互

**推荐：打开兼容且合法的项目后，自动触发一次异步重建。** 理由是用户已选择“重开现算”，无需再找按钮才看到世界。

明确规则：

- 先通过文件、输入、算法/依赖兼容检查，再切换会话并启动；错误文件不得破坏当前项目。
- 显示“项目已打开，正在按保存的配方生成”，阶段、已用时和取消入口可见。
- 不承诺立即出图；此时只有输入恢复成功，世界尚未恢复。
- 当前若有旧任务，先使其 epoch 失效并取消；等待资源退出期间显示等待，不并发启动昂贵全链。
- 自动启动只属于本次成功打开动作，不是持久自动重试队列。
- 用户在等待或生成期间编辑/撤销，自动请求即失效；保留新草稿，随后由用户点击重建。
- 用户取消或构建失败后不自动重试，给明确重建按钮。
- 后续日常编辑仍采用显式点击重建，避免每次拖动都运行全链。
- 未保存旧项目先保存/放弃/取消；保存失败中止切换。打开兼容新项目后，不继续把旧项目地图显示为新项目地图。

本交互已随整份 R2 获批准：兼容项目打开后自动生成一次，日常编辑仍显式重建。

## 7. 异步构建、取消与原子发布

每次任务只持有不可变输入与私有资源。最多一个实际全链构建；旧任务未退出时不启动第二个。编辑可继续，取消以协作检查点退出，不承诺即时停线程。按钮反馈、worker 停止、资源释放分开测量。

草稿提交、取消、open/new 会撤销当前请求发布资格。编辑后又撤销成相同配方也不能复活已取消的 request。发布前同时检查 epoch、build ID、revision、取消状态与候选完整性。

失效由真实 artifact 依赖驱动；保守以捆绑 formation 重建为基础。只允许按真实依赖复用 climate work domain 等已有结果，不承诺只跑 P5 或局部空间重算。

发布包必须一致覆盖世界、水文/气候、FieldDocument、面积摘要、拾取身份、表面关联、河线、2D/3D 显示资源和报告。先验证候选并准备独立显示资源，后在主线程一次提交；失败保留旧世界与旧资源。

保留现有延后一 pass 的取消机会，并在提交前重查。发布前已被 UI 消费的取消优先；提交后该请求不再可取消。

当前结算路径先更新 formation_surface 再判断取消，需要核实其缓存键与所有消费者；证明仅是私有可再生缓存才可独立保留，否则纳入事务。这里只记录待验证风险，不宣称已复现缺陷。

发布不得恢复旧相机覆盖用户最新视角。后台 LOD、河线、投影等任务同样绑定发布身份；晚到旧结果不得装到新世界。失去对应实体时清空选择，不按易变数组索引误绑。

## 8. 撤销重做与缓存边界

undo/redo 即时恢复输入事务，不反向编辑生成数组。恢复到当前发布输入时可直接确认匹配；否则地图保留旧版并标明待重建，由用户点击。

不保证每次 undo 即时恢复世界，不保存历史世界快照。首期仅必保当前有效世界和构建候选；输入历史限会话内，重开建立新历史根。失败不改作者意图、不加历史项、不清 redo。

内存缓存只影响速度，永远不是 SSOT。缓存必须完整、验证通过、身份匹配；不能以缓存命中绕过发布检查。缓存丢失/驱逐/损坏应能回退冷构建。陈旧候选默认丢弃。

性能优化可评估有实际消费者的内存缓存，但必须报告占用与命中条件，不能引入持久世界或阶段缓存。不能以“为了性能”悄悄恢复用户已否决的快照存储。

## 9. 项目格式、保存与兼容

### 9.1 最小文件

推荐 UTF-8 JSON 单文件，扩展名 .sekai.json。科学内容仅为输入配方及解释它所需的生成身份；附带少量格式、安全校验和非科学偏好元数据。

| 内容 | 约束 |
| --- | --- |
| magic、项目格式版本 | 与领域输入 schema 版本分开 |
| 配方与输入 schema/指纹 | 所有生成所需作者值，复用领域事实源 |
| 生成身份 | pipeline/stage、规则/依赖内容哈希、profile/数值策略版本 |
| writer 版本/commit | 诊断，不代替生成身份 |
| 可选项目名、视图偏好 | 不参与科学生成，不含派生地图 |
| 普通 extensions | 仅非语义扩展可原样往返 |
| 校验和 | 发现损坏，不代表可信签名 |

不保存世界、阶段缓存、历史快照、求解轨迹、稠密场、网格、GPU 资源、线程或运行任务。运行耗时报告可作为独立研发测量记录，但不是项目可恢复世界的数据，也不应含隐式世界转储。

现阶段不引入空泛作者约束或规则插件框架。依赖不能只指向原机器绝对路径；现有内建数据以内容身份标识。未来外部数据若出现，再明确其可移植打包/缺失契约。

### 9.2 保存事务

保存捕获特定配方 revision；保存期间继续编辑，成功只标记捕获内容已保存。非法未提交控件文本先纠正或取消，不悄悄保存成另一个值。

同目录临时文件 → 编码写入 → 同步与校验 → 平台替换 → 确认成功后更新保存身份。已有配方文件保留可恢复备份；该备份仍只是配方，不是世界快照。

磁盘满、锁定、权限、外部文件修改、替换失败均不能清除未保存标志。冲突提供另存为或明确覆盖。失败报告实际旧文件、备份、临时文件位置，不宣称任意 rename 都具有断电绝对安全。

Windows ReplaceFileW 的错误可能改变文件位置；备份和恢复逻辑须遵循其真实语义，不能只处理布尔失败。[Microsoft 官方文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

既有应用自动持久化不得静默覆盖显式项目。恢复候选只含输入，标明未保存会话，由用户选择；本期不增加世界恢复日志。

### 9.3 加载与升级边界

临时解析并验证：格式识别、大小/嵌套限制、校验和、schema、显式迁移、领域约束、算法与依赖兼容；通过后才提交新会话。失败保留当前会话。

未知核心版本、影响生成的未知字段/枚举、未知算法或缺失依赖均明确失败，不以 serde(default) 或忽略字段静默改变意义。普通 extensions 可以保留，不准用它藏生成语义。现有 ReliefSpec 的严格反序列化约束不能绕过。

输入 schema 可迁移与生成结果兼容是两回事。schema 转换成功不表示旧世界可按原语义重建。

原生成身份不匹配时停止自动生成，列出差异。用户可取消，或明确选择“用当前生成器升级为副本”；副本记录原生成身份和迁移来源，原文件不覆盖。副本按新身份重建，不能声称恢复了原世界。随后保存副本使用新身份，不把其结果冒充旧身份结果。

只承诺经过验证的具体版本迁移，不承诺所有历史自动存储可直接导入；现有参数可经明确的另存为项目流程导入。

### 9.4 再现承诺

恢复作者输入要求 schema 可识别；按原语义重建要求原算法/依赖可用或存在明确验证的兼容实现。相同 seed 远远不够；还需要匹配参数、profile/分辨率、拓扑、数值策略及依赖内容。

精确逐位复现还受浮点平台、工具链/数学库等环境影响。遵循 audited_float_platform 的边界：科学不变式所有支持平台都要过，精确指纹只在审计环境验证。跨平台重新生成可能不同，不能静默标作精确恢复；显示环境差异并要求用户确认继续跨平台重建。

旧生成器不存在时保留原配方并明确无法按原版重建；不自动下载执行旧代码，不自动替换算法。本期不承诺旧生成器永久归档。用户已选择不存快照，因此接受的是保留配方与版本要求，而不是无条件长期保留原地图结果。

## 10. 地理正确性与错误恢复

### 11.2 每轮不可省略的闭环

1. **固定对照条件。** 同机、相同输入/seed/profile/生成身份、同构建配置、同缓存条件和同操作场景，先测改前。
2. **定位瓶颈。** 结合端到端计时、stage/内部 span、CPU/分配/上传等实际证据，写出成本位置和可检验假设。
3. **一次受控优化。** 一轮只验证一个可归因的改动；注明输出是否应逐位不变、预期影响和回退边界，不同时混改科学机制。
4. **配对复测。** 同条件测改后，保留原始值、缓存冷热、质量状态及噪声说明；必要时重复相关对，不能挑最好的一次。
5. **科学正确性及 UI 回归。** 验证身份、领域硬约束、受影响契约及 2D/3D 操作/发布/取消行为；不以速度收益替代正确性。
6. **保留或撤回。** 收益可重复且超过观测噪声、质量及 UI 不退化才保留；无收益、不可归因或不满足契约则撤回该轮优化，不混撤用户其他工作。
7. **更新基线并再判断。** 重新看瓶颈，决定下一轮，而不是按预先猜测连续堆优化。

本节是设计上的验收流程，不是已授权执行的实施任务表。工程等价优化应尽量维持现有输出身份；若输出改变不能证明是错误修正或现有已批准数值策略的等价实现，应停止并进入独立设计裁定，不能以“优化”名义绕过算法版本和科学审阅。

### 11.3 证据驱动的调查顺序

下列是先调查后选择的优先顺序，不宣称某类一定最优；测量显示别处更重要时调整，并记录依据。

| 调查顺序 | 可考虑内容 | 进入优化的证据和限制 |
| --- | --- | --- |
| 1. 冗余工作 | 同一请求重复构建/验证/派生、无变化却重算或重复上传 | 必须证明重复且可安全复用；不得删除必须的边界校验，只能复用明确有效的验证结果 |
| 2. 数据布局与分配 | 热循环临时分配、复制、非连续访问、可复用工作区 | 实际剖面显示显著成本；保持运算次序、精度和边界语义，不先做大规模布局重写 |
| 3. 派生显示与提交 | LOD、河线、投影、字段准备、GPU 上传和主线程安装 | 测到对应耗时/长帧；不降低 LOD 质量、不改变 T1 候选、不以降低默认档位达标 |
| 4. 内存缓存与失效 | 已验证且身份匹配的表面、工作域、表现派生结果 | 有真实命中和内存收益证据；冷热分报，不持久化；不虚构 P2–P5 细粒度缓存 |
| 5. 调度与任务粒度 | 废弃请求、重复唤醒、主线程阻塞、测得适合的工作粒度 | 不重做已证伪的小粒度并行；只有工作量或上下文改变且新证据支持时才重新审阅 |

如果当前测量仍显示主要成本在已知求解器结构，而上述工程机会不足，报告已达当前允许范围的收益边界。不得为了“反复优化”无意义地重做失败方案，也不得偷偷引入模分裂、FAS 周期/网格调整、CFL/迭代策略变化等尚待裁定工作。

A6 已撤回细网格并行：线程唤醒吞掉收益；本期不是重跑理由。A6 已采用瞬态梯度普通投影：沿用现有决定，不将同一变化重复计为新收益。冻结规格中适用的既有判据继续有效；不能把某一 A6 子任务的收益阈值擅自泛化成所有优化的新统一门槛。
