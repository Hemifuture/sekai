# Civ Atlas 地形直接移植与 Sekai 气候耦合

状态：用户已批准并要求执行到彻底实现（2026-11-01）；最终用户 UI 验收独立保留。
独立可实施性审阅已完成：未发现阻碍制定实现计划的重要未决问题。

## 1. 用户决定与修订

用户认可亲自查看的 Civ Atlas 地形，要求停止自行开发替代地形方法，直接复刻其
地形生成方法，再与 Sekai 气候模块耦合；用户明确接受 AGPL 路线与源码直接移植。
这取代此前海岸实验规格中“不复制上游源码、仅借鉴多尺度形状”的本轮路线限制。
保留守恒、最终态一致性、版本身份、支持尺度与用户 UI 验收要求。

方案比较：直接移植可保留上游算法并在应用内重建，用户已选择；只导入导出地形
适合验证但不能代替集成生成；重新独立实现相似噪声轮廓不满足用户此次意图。
本次不重开这项选择。

## 3. 核心边界

主要计算仍在 Rust；TypeScript 仅作离线参照，不成为应用运行时依赖。
移植内容包括随机子流/舍入约定、球面网格与几何、大陆/板块形状、抬升与海底、
侵蚀与湖泊处理，以及构成可见地形的细岸/河谷步骤。不能只移植 `tectonics.ts`。
不移植文明、历史、账号、AI、网页 UI 和无人消费的形成过程历史。

上游 `world.ts` 在侵蚀中使用其降水估计；第一阶段保留这一初始化依赖，以验证地形
忠实度。它只作为作者地形初态的私有生成步骤，不发布为 Sekai 气候，也不称作双方
气候已经反馈收敛。后续更换该降水输入必须单独对照，不偷偷改变第一阶段基线。

上游 `raster.ts` 不只是着色：会改变细高程与岸线。凡改变高程、海陆或水面连通的
步骤，须进入权威细地形，先于 Sekai 气候强迫构造；纯法线/阴影装饰可留在显示层。
不得发布粗格海陆，随后只在画面上挪海岸却沿用旧水文。是否能保留上游视觉而满足
这一边界，是首轮验证问题，不预先宣称成功。

## 4. 数据与接入

现有 `causal.rs` 强制先构建 P2/P3，并让 P5 读取其身份；不能为兼容接口伪造
演化板块历史或基底账本。新增平行的地形来源，发布已验证的地形快照，采用枚举接入
现有生成入口；旧路径在新路径验收前保留用于旧配方和对照。

地形快照至少绑定：上游提交/生成器版本、种子和参数、球面空间身份、米制高程、
海底、海陆/湖泊及水面、有效尺度、初始水库存、初始化来源和细地形身份。
具体 Rust 类型在实现计划阶段按真实消费者收敛，不提前扩展通用导入框架。

首个保真场景使用上游海平面与水面作为初始化输入，按选定球体尺度积分形成初始
水库存，而不是套用旧默认库存再淹出另一条岸线。此后按该库存守恒；用户主动改变
水量属于新输入与新身份，必须重算地形水体和气候，不承诺仍与原参照图一致。

`GlobalClimateForcingBuilder` 内已有私有输入边界：高程、水面几何、相对渗透性和
空间/内容身份。复用该强迫构造与 C2 求解器，新增受验证地形的适配入口，不复制
强迫算法。Civ Atlas 没有直接提供 Sekai 的完整材料与渗透性账本：先审计哪些现有
有出处的初始化可复用，缺失字段明确不可用，不填写假历史或任意数值来通过校验。
若材料闭合不足，允许离线地形保真对照推进，但不能把耦合发布标为完成。

保留上游原生网格作为参考。映射到 Sekai 空间域前后比较陆地面积、海陆连通、
海湾/半岛/岛链以及高程；不得因为现有格元方便而先接受轮廓损失。
粗气候域由同一权威地形聚合，显示叶片读取该地形，点选同源；父层面积/水量一致。
第一步先审计粗细表示的实际支持尺度，再定支持档位与误差预算，不先宣称全部 LOD 有效。

## 5. 分阶段耦合

第一阶段：忠实移植的地形初态 → 水体与物质初始化 → Sekai 气候 → 使用该气候的
最终水文 → 原子发布。地形在该阶段的气候求解中固定，不再次经过旧 P5 改形。
重新计算的河流流量和河网必须匹配我们的降水；上游河谷可作为初态地貌保留，
不能把上游旧流量冒充新气候下的流量。湖泊水面与汇流若存在相互依赖，须先闭合再发布。

第二阶段：仅在第一阶段通过后，评估以 Sekai 降水/径流驱动移植侵蚀器的有界反馈，
按已有来源选择演化时窗；地形改变后重新构造气候、水文和身份，最终一次发布。
不承诺无限平衡、不为追求原图逐像素一致压制真实反馈；反馈造成的形状变化单独展示。
第一阶段通过只意味着单向耦合，不宣布完整地形—气候双向耦合完成。

## 6. 最小充分验证与 UI

先固定用户认可的一个场景，不扫描种子挑好图。建立上游真实页面/原始输出与 Rust
对应输出的全图、同投影近景；分开检查粗网格和细地形，不以调色掩盖形状差异。
参照版本和参数必须记录；同 seed 跨生成器不自动代表同一世界。

忠实性优先精确检查随机子流/离散拓扑等可精确部分；浮点差异先测再制定可接受
误差。科学不变式不能因浮点金丝雀不匹配而跳过。无依据的形状评分和阈值不新增。
需要扩大语料时，按已发现的极地/接缝/窄水道风险选择最小夹具，而非默认全档多 seed。

UI 提供明确的 Civ Atlas 地形来源与来源版本、生成/取消、当前参数；可查看地表、
海陆、气温、降水、风、河网和站点。支持范围或缺失材料字段可见，不显示伪造的
P2/P3 历史。保存配方绑定新来源与版本，旧配方不静默升级或重建为不同世界。
每次改变生成结果提升对应阶段及配方生成器版本。

分别记录地形、适配、气候、水文、LOD/GPU 与端到端耗时及内存；性能测量串行、
固定次数和时限，不将隐藏缓存或预览算作发布。无需 UDP 或网络压力测试。
达到既有时延目标与保真效果需要实测，不能从 Civ Atlas 速度推断耦合后的速度。

验收步骤：启动实验构建，选择新来源及固定场景；与上游全图和近景比较大陆/岸线；
切气候和河网、放大、点选与站点读数；取消后重建、保存重开，检查身份和来源。
用户本人 UI 确认前不标记地形替换已交付。

## 修订 A3：细地形权威与湖床初始化（执行期实测，2026-11-01）

原 `rasterWindow/shadeSphere` 随显示 scale 改变实际高程和海陆，gully 在 zoom 分支
也写入高程；因此固定一个规范尺度并绑定身份，显示 LOD 不再改变该尺度。
移植保留原 scale=1 柔化底图、噪声、河谷、沟壑及河口数据，按需批量求值，
不分配全球高倍栅格。候选尺度来自原 UI 的 2 的幂细节级别，测量后再钉产品支持域。
原版像素中心的精确对照与任意方向查询扩展分别验证，不能假称整图和 zoom 是同一地形。

一次原始源码测量（同一 seed42 默认世界、首河口/首湖/固定接缝三个窗口，S=2/4/8）
确认显示湖面不是物理水位：首湖节点床面为 3870.12255859375 m，水位为
3877.7060546875 m，邻近 S4 lake 像素的显示高程为 4222.17529296875 m。
这是测量记录，不是新增阈值；原报告为执行记录中的 `window-reference.json`。

使用原三角形 P1 节点残差作为最小湖床初始化适配：令 `F` 为固定尺度原版细地形，
原湖节点 `i` 的 `δ_i = original_bed_i - F(node_i)`，其他节点的残差为零；
`B(q) = F(q) + Σ λ_i(q) δ_i`。`λ_i` 复用同一三角形重心基函数。
不加经验深度、过渡宽度或拟合系数；无湖节点的三角形直接保留原结果。
数学上恢复原湖节点床面并保持共享边连续；实际浮点误差必须测量。
本项会改变湖区及其局部岸缘，不承诺原绘图湖掩膜逐像素不变。

水位保留原 lake level 先验，物理湖边取实际床面上的连通截水区域，不用 noisy
water2 绘图掩膜。任务 4 给出床与湖先验，任务 5 使用实际 Priority-Flood 溢口和
合盆/库容闭合后才能发布完整水体。建立初始库存之前，超出真实溢口的先验水位
按有出口的库容约束排出并记录；建立库存后任何溢流必须计账，不能无声裁水。
同一相通水体不能带不同水位。若湖修正域实际触及海岸，须约束海岸零残差，
不静默移动原海岸；先测交界，未出现前不添加通用几何切割框架。

来源：上游 `raster.ts::cellPlanes` 的既有重心插值；标准 P1 节点插值性质见
Brenner & Scott (2008), *The Mathematical Theory of Finite Element Methods*,
https://doi.org/10.1007/978-0-387-75934-0 。此处仅用插值恢复已知初态数据，
不声称该文献提供湖泊成因模型。溢口复用上游与 Sekai 已有 Barnes (2014)
Priority-Flood。以上只用于初始化，不能在气候求解后以同一方式美化结果。

气候适配须读取同一细场的面积/体积与共享边湿长度；现有 P1 V1 类型及从粗高程
再次生成湿边的旧路径，不能冒充 Atlas 细场。湖与海分开，海深归一化按真实消费
语义验证；叶片和点选读同一求值结果，守恒聚合不等于简单中心平均。

### 修订 A3b：不为局部像素保真增加海岸切割器

默认世界 30 个原湖节点的邻接三角形实测：S2 的 17,529 个规范采样点无 raw 海洋；
S4 的 70,148 个采样点中有 2 个 raw 海洋像素，S8/S16 分别有 3/13 个。
它们位于原湖节点 23710 的邻接三角形 49025/49110 内部，是原 zoom 沟壑生成的
闭合负高程微孔，scale1 整图没有该海面。以上是交界见证，**不是总岸线改动数**。

这说明只切粗三角形边不能履行 A3 提出的逐点保岸承诺；零残差边界也不能自动
阻止非线性细场在内部再次过零。用户 A2 要求的是算法而非指定地图，故按极简原则
取消 A3 的“湖修正域触海仍必须保持原海岸不动”条款，不引入通用切割器、
距离 taper、深度截断或拟合系数。其余 A3 的节点残差、床/水位分责保持不变。

新边界：所有无原湖节点的三角形仍逐点返回原细场；原湖节点邻接三角形内允许
有来源的床面初始化改变海平面交线，实际符号变化数量和位置在验证记录中报告。
任务 5 必须从初始化后的 `B` 重建所有海/湖几何、初始水库存、气候强迫与最终水文，
不能沿用 raw 海湖掩膜；不得声称初始化后仍与原显示岸线处处相同。
这属于建立账本之前的显式初态约束，不授权求解后美化海岸或改变已发布科学状态。

## 修订 A4：固定床面阶段的最小材料输入

现有 P4 与 formation 水文的材料消费者只需要归一化 `relative_permeability`，
用于同一个 `formation_runoff_fraction`。阶段一采用明确的大陆结晶/大洋镁铁质
基底端元先验：从未启用板块编辑器的原生成结果保留
`plate_continental[plate[i]]` 这条逐节点来源位，选择现有 P3 基准端元。
不根据最终海陆倒推地壳，不制造零裂隙、零沉降或其他历史记录。

原端元表移至 `world` 的一个最小 helper，旧 P3 和新初始化共同引用，不复制数值。
该参数是既有归一化求解指标，不是实测绝对渗透率。来源位、初始化模型版本、
实际参数值和地形身份均进入新 artifact/配方身份。陆面蒸散/径流的聚合保留
陆地区域与参数的相关性，P4 与最终水文使用同一输入；不能只把整个格元平均参数
乘海陆比例而宣称自动闭合，也不能将负高程的内陆湖自动当海洋。

本项复用 `2026-07-29-geologic-substrate-design.md` 的归一化指标语义、
`2026-08-17-substrate-primary-relief-p3-design.md` 的基底类别/端元，以及
`2026-09-02-p4-land-evapotranspiration-design.md` 的 Manabe (1969) `E=P−R`
分配。数字仍是既有 Sekai 模型参数，不冒充文献实测常量。

固定床面阶段不搬运固体，不补造历史质量账或发布缺失的土壤、地下水、沉积物、
资源、地壳厚度等字段，也不声称“完整固体预算已验证”。若第二阶段启用侵蚀，
须另提供所选米制侵蚀律、时窗、抗蚀性、材料密度、可侵蚀层/沉积库存及出口账；
不能把本项归一化径流先验当成这些输入已经存在。

## 修订 A5：当前湖库存与当前流率，不强加湖稳态（2026-11-02）

固定床面阶段发布一致的当前快照：已初始化并验证的湖床、连通区域、水位和库存，
以及同一地形/水面 forcing 下现有 C2 对应的月均当前水文流率。月份是固定当前
几何下的气候诊断，不是假定这些湖已经走完一年预报。

不要求每个湖达到气候水文稳态，不新增无来源的湖蒸发/热容模型，不套用旧的
“一年入流灌满整格库容”判断来覆盖原库存。未满湖可以是当前汇流终端；如需
存储率，应准确标为由模型已解析通量计算的量。缺少独立湖蒸发等分量时，
可以发布明确命名的已解析净入流及未解析项，不能把它称作完整真实 `dV/dt`，
也不能把未提供的分量伪装为实测零。

保持几何/初始库存一致性、已声明机制的水账与既有 C2 预算门；不推进时间或
偷偷修改库存来消掉非零当前流率，不放宽物理门限，不制造平衡通量。
具体实现须明确干陆、海洋、淡水湖各面积与通量的归属，防止重复分配或漏计。
未解析过程通过能力/来源说明表达，不发布占位科学字段。

此裁定落实 AGENTS 的地图生成器“最终当前态而非预测模拟器”边界，及本设计
第一阶段固定床面的范围；只有后续明确采用湖过程模型与时域后，才评估其水位
演化和稳态，不能把那项研究变成本轮移植的隐含新增门禁。

### 修订 A5b：海盆使用来源锚点，不新增“只保留最大海洋”规则

初始化不能凭面积只选择一个负高程连通片：这会丢弃上游合法的第二海盆。

多个来源海盆可以分别保留。没有海洋来源锚、也未与之连通的新负洼地，
不因床高为负就自动成为海洋，湖先验与当前汇流另按 A3/A5 处理。

来源分类在这里仅确定初始海水来源，不复制成最终掩膜；所有边界、面积、
体积、湿边和气候输入仍由新 `B` 及真实连通结果重建。事实源是固定上游

## 修订 A7：共形过渡面保留红细分父身份（2026-11-02）

水体支持网格曾把局部共边过渡的质心扇当作普通三角形继续递归细化。
两三角形最小生产函数回归已证实：继续细化过渡子面时，原父面的长边仍被
保留；新增面数和面积下降并不保证最长边缩小。实际海岸运行另观察到重复
前沿并触发执行时限；最小回归证明结构风险，完整运行的因果修复仍须复验。

改用保留父身份的 red/green 细分：red 四分沿用现有归一化球面共享边中点；
green 只作临时共形闭包。green 需要进一步细化时恢复原父面并 red 四分，
不对 green 递归生成质心扇。出处为 Cervenka（2004），
《Three-Dimensional Mesh Generation for Device and Process Simulation》§2.6.1.1：
https://www.iue.tuwien.ac.at/phd/cervenka/node14.html 。
该出处支持父恢复策略，不直接证明球面版本；球面实现另以归一化中点的
直径收缩条件与多轮局部测试验证。若采用几何充分条件，须检查实际根面满足，
不能未经测量假定；执行内存/时间上限仍只是失败保护，不是成功收敛证明。

本修订只改变支持网格的构造，所有新增节点的床高仍调用同一 Civ Atlas
规范尺度生产求值器；不放宽间距，不改变作者地形、不拟合岸线，不减少
气候/水量约束。实际海岸连通、初始化库存与气候 forcing 随最终支持重建，
通过后记录运行规模、耗时和峰值内存。细分身份归新 Atlas 阶段版本管理。

A7 的球面进展依据：令根面最大短弧长为 `D0`，实现检查各根边端点点积为正，
即 `D0 < π/2`。对单位向量的归一化边中点 `m(a,b)=normalize(a+b)`，
由向量范数恒等式可得 red 子面最长弦长至多为父面的
`q = 1/(2 cos(D0/2))` 倍；该域内 `q < 1`。父面球面凸包内的归一化非负
组合保持这一局部域，临时 green 边也受 red 父面直径约束。因此有限 red
层级即可达到来自规范求值器的间距；green 后续提升原父面的规则防止产生
无此收缩性质的递归过渡扇。这里是球面归一化中点的直接推导，不是经验系数，
也不是将 Cervenka 的平面描述直接当作球面定理。最小多轮生产函数回归与
同一实际河口场景均已验证结束；验证范围按以下审阅澄清记录。

**A7 证据范围澄清（Task 5 审阅，2026-11-02）：** 原粗 source 的
`SphericalSurfaceSnapshot` 经过其自身的完整拓扑与几何校验；派生支持图的证据
包括共形构造、多轮局部 red 回归的边引用/Euler 检查，以及已记录的实际河口见证。
`AtlasTerrainSnapshot::validate` 检查 source 绑定、密集数组数值域、支持面的
owner/offset/index 引用、气候及质量报告绑定、已存格元体积与湖库存汇总、已存
routing residual 的容差和实际内容重哈希。它不独立重积分每个支持面，不从各终端
通量重新计算 residual，也不执行全球支持图的边双引用/Euler 或逐源格面积闭合。
因此本轮不得称为最终千万面支持图的独立全球拓扑与水体重算审计。这一证据边界
不表明构造结果错误，不新增全图门禁，也不改变已声明的性能、尺度及物理约束。

## 修订 A8：站点导出的真实来源与支持尺度（2026-11-02）
