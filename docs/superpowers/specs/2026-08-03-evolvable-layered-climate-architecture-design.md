# Sekai 可演进分层气候架构设计

日期：2026-08-03

状态：方向与模块边界已确认，等待书面规格复核

范围：自然世界的行星级大气—海洋环流、季节气候、年际变率和极端事件气候学

## 1. 决策摘要

Sekai 采用“有上限的分层气候核心 + 稳定语义诊断接口”路线：

- 保留闭合球面上的时间演化浅水动力学，不使用另一套快速稳态物理作为预览；
- 当前单层大气与单层表层海洋仅作为数值参考配置，不作为永久公共结构；
- 中期生产上限为两层活动大气、两层活动海洋和一个缓慢深海热库；
- 对流、云、垂直混合、海冰、积雪和陆面交换采用守恒的中等复杂度参数化；
- ENSO 类年际振荡与台风等极端事件作为独立、可审计的气候能力，不伪装成逐日天气或历史时间线；
- 水文、生态、UI 和存档只依赖稳定科学语义字段，不依赖内部层数和求解器类型；
- 完整三维非静力 GCM 不进入当前产品路线，但动力核心保留可替换边界。

该决策优先满足科学因果、桌面可运行、所见即所得、可复现和长期解耦，不追求没有校准依据的任意层数通用框架。

## 2. 目标与非目标

### 2.1 目标

1. 同一个生产时间演化模型既生成设计器结果，也作为科学事实源。
2. 从单层升级到分层、从 RK3 升级到 IMEX 时，不重写水文、生态或显示层。
3. 每个权威字段只有一个写入阶段，所有反馈都位于有界联合求解器内。
4. 模块沿几何、空间算子、层布局、物理过程、时间推进、诊断和产品编排等变化轴正交。
5. 保存的旧世界不会因应用升级而被静默改变。
6. 缺少某项科学能力时显式报告“未计算”，不把缺失误解释为零。
7. 所有阶段可独立验证、计时、缓存、取消和解释。

### 2.2 非目标

- 不解析单个云团、雷暴眼墙或全球天气预报；
- 不建设任意 `N` 层且任意闭合方案的用户可编程 GCM；
- 不让作者直接选择时间积分器、预条件器或层数；
- 不生成编年史、虚构年份或历史气象事件；
- 不把 AI 地球天气模型作为任意行星的物理替代品；
- 不要求气候网格与地表、地质或生态网格具有相同分辨率。

## 3. 科学能力上限

正式中等复杂度配置由以下部分组成：

```text
上层自由大气：高空风、急流、上层温度
        ↕ 对流、辐射、动量和水分交换
下层湿润大气：近地风、温度、水汽和降水
        ↕ 海气、陆气和冰气表面交换
海洋混合层：海表温度、表层流和季节储热
        ↕ 混合、上升流和温跃层交换
海洋温跃层：内部波、热含量和赤道耦合
        ↕ 缓慢交换
深海热库：非活动或低频更新的热量与盐度背景
```

两层大气用于表达垂直风切变、第一斜压模态、季风环境和对流闭合；两层活动海洋用于表达混合层热惯性、温跃层和 ENSO 类赤道波反馈。更多层只有在已批准的能力需求和量化收益证明后才增加。

完整三维核心若未来出现，必须通过同一个语义诊断输出边界接入，不能把三维内部状态泄漏给下游。

## 4. 方案比较

### 4.1 永久单层

优点是快且简单；缺点是无法自然表达垂直风切变、温跃层和年际耦合，后期必然产生破坏性重构。拒绝。

### 4.2 立即建设任意 N 层 GCM 框架

优点是表面上的最大通用性；缺点是闭合方案、参数、稳定性、UI 和性能都没有可校准上限，并会引入万能上下文和无真实第二实现的抽象。拒绝。

### 4.3 有界配置、内部层化、公共语义稳定

内部数据结构支持层轴，产品只发布经过验证的固定模型配置；公共结果按近地风、海表温度等科学语义发布。该方案保留主要扩展路径，同时避免提前承担完整 GCM 复杂度。采用。

## 5. 正交架构

### 5.1 单向依赖

```text
geometry ──→ horizontal_operators ──┐
layer_layout ────────────────────────┤
forcing ──→ local_physics ──────────┤
surface_boundary ─→ surface_exchange┤
                                     ↓
                              tendency_system
                                     ↓
                              time_integrator
                                     ↓
                              formation_solver
                                     ↓
                            diagnostic_projector
                                     ↓
                         SeasonalClimateSnapshot
                              ↓              ↓
                    variability_model  extreme_climatology
                              └───────┬──────┘
                                      ↓
                           CurrentClimateSynthesis
                                      ↓
                            水文、生态、UI、导出
```

依赖不得反向。数值模块不得导入 UI、字段调色板、生态或完整 `WorldSpec`。

### 5.2 模块职责

| 模块 | 唯一职责 | 禁止事项 |
|---|---|---|
| `geometry` | 球面单元、边、面积、邻接与坐标 | 不知道大气、海洋或温度 |
| `horizontal_operators` | 梯度、散度、通量、平流和切向投影 | 不管理月份、时间步和物理常数 |
| `layer_layout` | 层描述、索引、掩码和连续内存视图 | 不计算气候过程 |
| `dynamics` | 压力、动量、质量和旋转动力学 | 不管理形成循环和输出字段 |
| `local_physics` | 辐射、凝结、对流与层间混合 | 不访问球面邻居 |
| `surface_exchange` | 海气、陆气、冰气热量、水分和动量交换 | 不生成河流、生态或 UI 数据 |
| `tendency_system` | 组合快、慢和局地倾向 | 不决定积分算法 |
| `time_integrator` | RK3、IMEX 或分裂显式推进 | 不知道 ENSO、台风等产品概念 |
| `formation_solver` | 月份、年度形成、收敛、取消和工作区 | 不定义字段 schema |
| `diagnostic_projector` | 内部层状态到稳定语义字段的只读投影 | 不反向修改求解状态 |
| `variability_model` | 年际模态、振幅、周期与相位 | 不覆盖季节平均字段 |
| `extreme_climatology` | 极端事件概率、强度和重现期 | 不伪装逐日天气 |
| `pipeline` | 阶段排序、缓存、失效和错误上下文 | 不包含数值公式 |

模块边界不等于 crate 或 trait 边界。只有存在两个真实实现的策略轴才定义 trait；其余优先使用具体、小型、强类型结构。

### 5.3 允许的策略接口

- `TimeIntegrator`：至少存在 RK3 参考实现和 IMEX／分裂显式候选后定义；
- `DynamicalCore`：只有未来接入第二个完整核心时定义；
- `ClimateCapabilityModel`：只有同一能力存在两个可互换实现时定义。

禁止万能 `ClimateContext`、字符串服务定位器、全局可变状态和任意回调 hook。每个函数只接收实际需要的最小类型化输入。

## 6. 内部状态与公共事实

### 6.1 `ClimateLayerState`

求解器内部的瞬时状态，按“层 × 单元”结构分离连续存储，包括层厚、切向速度、温度和受控示踪物。它不是公共世界格式，水文、生态和 UI 不得读取。

层布局由经过验证的 `ClimateModelProfile` 创建。用户不能提交任意层数组。

### 6.2 `ClimateCheckpoint`

检查点只用于热启动、取消恢复和缓存。它必须匹配：

- 网格指纹；
- 输入规格指纹；
- 层配置；
- 物理模型版本；
- 数值算法版本；
- 量化和确定性协议版本。

任一不匹配即丢弃并重建。检查点可删除、可重建，不是世界真值。

### 6.3 公共快照

公共事实拆成不可变、可组合的类型化快照：

- `SeasonalClimateSnapshot`：十二个月平均态；
- `ClimateVariabilitySnapshot`：年际振幅、周期、方差和相位；
- `ExtremeClimateSnapshot`：概率、分位数和重现期；
- `CurrentClimateSnapshot`：在需要当前相位时，由明确的合成阶段生成；
- `ClimateQualityReport`：能力、收敛、守恒、适用范围和已知限制。

原始层字段可通过版本化诊断命名空间显示，但不能成为下游核心依赖。

## 7. 稳定字段契约

核心字段按科学语义命名，不按实现编号命名。例如：

- `climate.atmosphere.near_surface_wind.monthly_mean`；
- `climate.atmosphere.upper_wind.monthly_mean`；
- `climate.atmosphere.vertical_wind_shear.monthly_mean`；
- `climate.surface.air_temperature.monthly_mean`；
- `climate.surface.precipitation.monthly_mean`；
- `climate.ocean.sea_surface_temperature.monthly_mean`；
- `climate.ocean.surface_current.monthly_mean`；
- `climate.ocean.thermocline_depth.monthly_mean`；
- `climate.cryosphere.sea_ice_fraction.monthly_mean`。

每个字段 schema 必须声明：稳定 ID、语义版本、单位、空间域、时间支持、统计含义、有效范围、缺失策略、权威阶段、精度和适用能力。

不得在同一 ID 下改变单位、时间含义或科学语义。语义改变必须发布新字段版本。

## 8. 时间语义与能力声明

以下时间类型不得混装：

- `MonthlyClimatology`：十二个月长期平均；
- `AnnualStatistic`：年平均或年总量；
- `CurrentClimateState`：当前切片相位；
- `InterannualVariability`：振幅、周期、相位与方差；
- `ExtremeStatistic`：超过概率、分位数与重现期。

快照显式携带能力集合，例如：

- `SeasonalMeanV1`；
- `VerticalStructureV1`；
- `SeaIceV1`；
- `LandSurfaceFeedbackV1`；
- `EquatorialVariabilityV1`；
- `TropicalCycloneClimatologyV1`。

每项能力使用三态可用性：

- `Unavailable`：本次快照没有运行或不支持该能力；
- `EvaluatedNotApplicable`：能力已经运行，并依据行星条件判定该现象不适用；
- `Available`：能力已经运行并发布结果。

因此“没有运行台风模块”与“经过评估后该行星不可能形成热带气旋”不会混淆。消费者必须声明所需能力；`Unavailable` 返回 `MissingCapability`，不能静默退化；`EvaluatedNotApplicable` 可以发布带原因和适用域的零风险结果。

## 9. 阶段所有权与反馈

### 9.1 唯一字段写入者

- `SeasonalClimateStage`：季节平均风、温度、海流、湿度、降水和冰雪；
- `ClimateVariabilityStage`：年际模态、周期、振幅、相位和方差；
- `ExtremeClimatologyStage`：极端风雨、洪旱和气旋重现期；
- `CurrentClimateSynthesisStage`：平均态与当前异常合成后的当前字段；
- `HydrologyStage`：河流、湖泊、径流和地下水；
- `EcologyStage`：生物群系、生产力、扰动响应和恢复属性。

任何阶段不得覆盖其他阶段的权威字段。

### 9.2 有界联合反馈

海冰—反照率、土壤水分—蒸散、植被—粗糙度等必须反馈气候的过程，封装进单个 `CoupledSurfaceClimateStage`：

1. 接收最小地表边界和行星强迫；
2. 在内部迭代气候与地表状态；
3. 使用明确残差、最大迭代次数和预算闭合条件；
4. 只有整体成功后原子发布；
5. 失败时不发布半收敛字段。

联合阶段中的植被只允许使用为能量和水量闭合服务的 `ClimateVegetationProxy`，例如覆盖度、叶面积与粗糙度；它不是最终物种或生态群落。最终河网和生态不能反向调用气候生成器。若未来证明某反馈必要，应把最小物理代理提升到上述联合阶段，而不是让完整生态阶段形成依赖环。

## 10. 气候网格与地表网格

气候网格独立于地表、地质和生态网格。默认使用 cubed-sphere；地表可以保持更高分辨率。

专用 `ClimateSurfaceRemapStage` 负责：

- 面积守恒地重映射降水、辐射、蒸发和其他通量；
- 对温度等强度量进行有界插值；
- 将三维切向风和海流插值后重新投影到目标切平面；
- 将海冰、陆海和云量作为分数而非最近邻分类重映射；
- 记录源网格、目标网格、方法和误差预算。

重映射结果是派生字段，不能取代源气候快照。更换地表显示分辨率只重跑重映射和下游，不重算气候。

## 11. 数值求解路线

### 11.1 参考求解器

当前显式经典 RK3 保留为小网格、高可信回归参考。它不进入同步交互路径，也不因生产优化而删除。

### 11.2 生产候选

首选比较：

1. IMEX／半隐式：隐式处理线性重力波和必要的旋转耦合，显式处理慢平流与局地物理；
2. 分裂显式：慢过程使用大步，快波使用小的局地子步。

二者使用相同空间算子、物理模块、层状态和诊断投影。胜出者必须通过与 RK3 的同方程一致性门，而非仅按速度选择。

### 11.3 输运

一阶迎风保留为鲁棒参考。生产输运升级为带单调限制器的至少二阶守恒有限体积方案，并满足：

- 水汽、层厚和冰分数不产生非法负值；
- 不在锋面附近产生不可控过冲；
- 共享边通量成对守恒；
- 球面六面接缝不产生独立修补逻辑。

## 12. 年际变率与极端事件

### 12.1 ENSO 类模式

年际模块计算一般化的“赤道海气耦合模态”，不能给所有行星强行安装地球 ENSO。资格和行为至少依赖：

- 跨赤道海盆几何和尺度；
- 行星旋转与赤道波传播；
- 混合层和温跃层结构；
- 东西向海温梯度；
- 风应力—海温反馈强度；
- 阻尼和季节锁相。

季节平均形成仍可求周期基线；年际异常由独立耦合状态推进或求统计吸引子。不得继续用“相邻两年相同”判定含 ENSO 状态收敛。

### 12.2 热带气旋气候学

全球核心不解析眼墙。极端事件阶段根据海表温度和海洋热含量、近地涡度、上下层风切变、湿度、纬度与引导气流，生成确定性种子驱动的统计—动力气旋集合，并发布：

- 生成概率与季节；
- 路径密度和登陆走廊；
- 强度分布与标准重现期；
- 极端风、雨、风暴潮潜力；
- 海岸侵蚀和生态扰动强度。

这些是气候统计，不是历史事件列表。其他极端能力遵循相同模式，拥有独立字段和版本。

## 13. 缓存、失效与确定性

缓存键只包含阶段声明的相关输入、阶段 ID、模型版本和算法版本。

必须满足以下失效关系：

- 调色板或说明变化不失效自然计算；
- 增加只读诊断不失效动力学；
- 改变气旋参数只失效极端事件及其下游；
- 改变层配置失效季节气候及真实下游；
- 改变地表显示网格只失效重映射及下游；
- 更换时间积分器改变算法指纹，但不改变公共字段 schema。

根种子按稳定阶段和能力命名空间派生。并行归并顺序固定；影响分类和实体生成的阈值使用规范化量化。循环内不得使用全局 RNG。

## 14. 版本与存档迁移

三类版本严格分离：

1. `schema_version`：文件和序列化结构；
2. `model_profile_id/version`：科学模型与层配置；
3. `algorithm_version`：积分器、通量和线性求解实现。

迁移规则：

- 增加可选字段可向后兼容；
- 改变字段意义或单位必须创建新语义版本；
- 旧世界默认使用其原模型配置加载；
- 用户选择新模型时执行明确“重新生成”，并提供字段差异报告；
- 应用升级不得静默重算并改变旧世界；
- 未知但结构合法的可选字段尽量保留；
- 不兼容核心字段明确拒绝，不猜测转换。

改变文件排布叫迁移；改变科学结果叫重新生成。

已保存的稳定语义快照是旧世界的可查看事实，即使相应旧求解器未来不再随应用分发也必须能够读取。精确重建只有在对应模型与算法兼容实现仍可用时才承诺；否则明确标记“可查看但不能原版本重算”，并允许用户选择新模型生成一个可比较的新版本。

当前球面环流分支仍是未接入生产存档的原型，因此允许在首次生产接入前一次性建立新契约；接入后遵守上述兼容规则。

## 15. 错误、取消与原子发布

错误至少分为：

- 输入或参数无效；
- 能力或模型配置不支持；
- 时间步稳定性失败；
- 隐式线性求解失败；
- 形成过程未收敛；
- 质量、能量或交换预算越界；
- 非有限或越界输出；
- 存档、检查点或迁移不兼容。

错误包含阶段、模块、月份、层、残差、阈值和必要的空间上下文。

允许自动改变数值路径，例如减小时间步、热启动改冷启动或更换预条件器；禁止自动放宽守恒／收敛阈值或换用另一套物理。所有恢复路径写入 `BuildReport`。

设计器始终显示上一次成功快照及其输入指纹。新请求异步执行，只有完整验证后原子替换；失败保留旧结果。过期请求以内容世代 ID 丢弃，不能覆盖更新输入。

## 16. 分阶段演进

### C0：契约与层栈基础

- 将硬编码单层内部状态改为层化存储；
- 建立公共诊断、能力集合、检查点和质量报告；
- 保持当前 RK3 单层参考结果在容差内不变；
- 不接入 UI，不改变现有生产气候字段。

### C1：可生产的单层时间演化

- 实现并比较 IMEX 与分裂显式候选；
- 引入工作区复用、确定性并行和取消点；
- 升级单调二阶输运；
- 接入异步缓存和稳定诊断显示；
- 仍使用一个活动大气层和一个活动表层海洋层。

### C2：中等复杂度分层核心

- 两层大气；
- 混合层与温跃层海洋；
- 层间动量、热量和水分交换；
- 垂直风切变、上层风与温跃层诊断。

### C3：地表与冰冻圈反馈

- 云、对流和辐射闭合；
- 海冰、积雪和反照率；
- 土壤水分、蒸散和地表粗糙度；
- 有界联合气候—地表形成阶段。

### C4：年际变率与极端气候

- 一般化赤道海气耦合模态；
- 热带和温带气旋气候学；
- 干旱、洪水、热浪和火险统计；
- 当前气候相位合成。

### C5：最终生态气候接口

- 水文与生态只消费稳定语义和质量字段；
- 生态使用平均态、季节性、变率和扰动重现期；
- 全阶段解释、能力标记和差异报告完成。

每一级必须独立通过验收后才启用下一能力；新能力不得借机重写已稳定的无关模块。

## 17. 科学验收门槛

### 17.1 通用数值不变量

- 球面面积闭合、跨面邻接和共享边配对通过解析测试；
- 无源、封闭动力测试每模拟年相对层质量漂移不超过 `1e-8`；
- 含源汇的质量与能量预算残差除以“对应交换绝对总量与参考储量变化二者的较大值”后不超过 `1e-6`，避免零交换测试出现未定义比值；
- 共享边两侧法向通量在浮点舍入范围内等量反向；
- 层厚严格为正，比湿非负，海冰分数位于 `[0, 1]`；
- 所有速度保持球面切向，海岸法向海流为零；
- 相同输入、配置和目标平台协议产生相同量化字段哈希。

### 17.2 生产积分器对 RK3 参考

在共同小网格、共同空间离散和共同物理下：

- 月风场和洋流矢量相关至少 `0.995`，归一化 RMSE 至多 `0.05`；
- 月温度相关至少 `0.999`，面积加权偏差绝对值至多 `0.1 °C`；
- 月降水空间相关至少 `0.98`，年总量相对偏差绝对值至多 `1%`；
- 形成周期、守恒预算和能力集合一致；
- 任一指标失败时，候选不能成为生产求解器。

这些是同方程数值替换门，不适用于不同科学模型版本之间的比较。

### 17.3 标准科学夹具

每个能力至少覆盖：

- 静止平衡、固体旋转、山岳流和不稳定急流；
- 水行星、两海盆和复杂类地海陆；
- 两层斜压模态、垂直风切变和层间交换；
- 海盆风生环流、赤道 Kelvin／Rossby 波和温跃层响应；
- 海陆季风、雨影、冰线和土壤水分反馈；
- 有资格与无资格产生 ENSO 类模态的对照行星；
- 有利与不利热带气旋环境的对照场。

新增 C2–C4 能力在实现前必须拥有自己的量化夹具规格；本总设计不允许用“看起来合理”代替能力验收。

## 18. 产品性能门槛

参考门槛以 Release、原生桌面、固定参考机器和冷缓存报告；WASM 单独报告，不用原生数字冒充。

- UI 提交参数和进入更新状态不超过 `100 ms`；
- 取消或识别过期任务的延迟不超过 `250 ms`；
- C1 单层 `n=24` 冷形成目标不超过 `10 s`；
- C2 四活动层 `n=32` 冷形成目标不超过 `30 s`；
- C2 四活动层 `n=48` 高质量后台形成目标不超过 `120 s`；
- `n=48` 核心工作状态、工作区和气候输出合计不超过 `512 MiB`；
- 固定网格下活动层数翻倍，峰值内存增长不超过 `2.2×`，不计科学上额外形成年的运行时间增长；
- 时间步内不得发生与单元数成比例的堆分配；
- 静态画面不重复重映射、上传或重建气候字段。

这些是产品准入目标，不通过就继续优化或降低默认能力，不得用另一套不一致物理伪装预览。分辨率是显式世界质量配置；后台计算期间显示上一次同质量、已收敛结果。

## 19. 测试与审计

### 19.1 单元与性质测试

- 几何、算子、层索引和掩码；
- 常量零梯度、通量配对、切向投影和正值保持；
- 局地物理交换成对闭合；
- 时间积分器阶数、稳定界和取消安全点；
- 字段 schema、单位、时间支持和能力检查。

### 19.2 集成与回归

- 固定行星夹具的形成、守恒和跨分辨率统计；
- RK3 与生产积分器同方程比较；
- 原生与 WASM 的量化字段哈希；
- 存档往返、旧 schema 迁移和不兼容拒绝；
- 检查点指纹拒绝与冷启动恢复；
- 失败不发布半快照、过期任务不覆盖新结果。

### 19.3 正交性测试

建立参数变化—阶段失效矩阵，至少验证：

- UI 样式变化不改变任何自然内容哈希；
- 新增只读诊断不改变求解状态哈希；
- 极端事件参数不重算季节平均气候；
- 地表目标网格变化不重算源气候；
- 时间积分器变化不改变字段 schema；
- 增加无关能力不改变已有随机流；
- 下游模块无法通过公开 API 修改上游快照。

## 20. 完成定义

本架构进入实施计划前必须满足：

1. 层数、时间积分、物理参数化、诊断和产品阶段具有单向依赖；
2. 当前硬编码单层状态有明确迁移目标；
3. 公共字段不暴露内部层编号；
4. 能力缺失、模型版本与算法版本均可区分；
5. 气候和地表分辨率通过守恒重映射解耦；
6. 所有反馈位于有界联合阶段；
7. RK3 参考、生产候选和一致性门定义完整；
8. 科学、性能、确定性、错误和存档门槛可自动验证；
9. C0–C5 每一级可独立交付且不要求预建完整 GCM；
10. UI、生态与水文只依赖稳定、不可变的语义快照。
