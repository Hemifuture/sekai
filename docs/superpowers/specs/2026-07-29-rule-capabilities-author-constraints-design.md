# Sekai 规则能力与作者约束设计

日期：2026-07-29
状态：实现前自审通过
上游设计：`2026-07-28-sekai-current-slice-world-design.md`
上游实现：世界基础引擎、独立字段显示、构造自然基础

## 1. 摘要

本切片建立第一套真实可用、确定性且不执行任意代码的规则能力与作者约束系统。

它解决的核心问题不是“如何加载一个万能 mod”，而是如何让规则包和作者输入通过受控语义接缝影响现有生成阶段，同时继续满足：

- 每个权威字段只有一个写入阶段；
- 规则不能绕过阶段图、缓存、验证和诊断；
- 普通规则包与世界法则包权限不同；
- 加载顺序不能决定语义；
- 硬约束冲突必须失败并定位来源；
- 软约束与提示必须确定性归并；
- 规则审计信息变化不能无谓失效自然生成；
- 第一阶段不执行脚本、动态库、网络请求或任意代码。

首个真实能力接入现有构造输入：

1. 世界法则包必须唯一提供构造模型能力；
2. 普通规则包、世界法则包和作者可以提交强类型构造控制约束；
3. 规则解析器输出完整审计产物；
4. 独立投影阶段只发布自然生成实际消费的最小构造输入；
5. `TectonicStage` 不读取规则包、作者对象或 UI。

默认内置世界法则包选择当前已经验证的 `CurrentSliceV1` 构造模型。没有额外约束时，种子 42 的自然结果与当前金图保持完全一致。

## 2. 已确认的边界

### 2.1 包含

- 稳定规则包 ID、能力 ID、规则项 ID 和语义版本；
- 规则包清单、内容哈希、核心 schema 兼容范围；
- 规则包依赖、能力提供和能力消费；
- 普通规则包与世界法则包权限；
- 唯一必需能力和可归并能力；
- 内置能力注册表；
- 内置类地球当前切片世界法则包；
- 强类型作者约束集合；
- 强类型规则包构造约束；
- 硬约束、软约束和提示；
- 构造控制的确定性离散求解；
- 硬约束冲突定位；
- 规则包依赖排序和循环检测；
- 规则解析审计产物；
- 最小构造输入投影产物；
- 正式阶段图与缓存接入；
- 应用默认规则集和只读状态摘要；
- 契约、性质、阶段、缓存、平台和回归测试。

### 2.2 不包含

- 任意脚本、Lua、WASM 插件、动态库或原生代码加载；
- 文件发现、下载、签名、沙箱或包管理 UI；
- 项目存储和 schema 迁移；
- 规则包启停 UI；
- 作者约束编辑 UI、撤销重做或局部失效；
- 魔力场、地脉、异常或具体魔法内容；
- 热量、水分、风、生态或社会作用量；
- 直接地形变形或最终字段覆盖；
- 板块种子、速度、地壳边界等空间对象级约束；
- 完整 `NaturalSnapshot` 或 `WorldSnapshot`；
- 历史事件、日期、时间线或时间积分。

这些能力需要后续独立切片。当前切片只建立已经被现有构造阶段真实消费的最小闭环，不创建空壳 forcing API。

## 3. 方案比较

### 3.1 方案 A：通用 JSON 参数字典与加载优先级

做法：

- 规则包提交任意键值；
- 后加载者覆盖先加载者；
- 生成器按字符串读取需要的参数。

拒绝原因：

- 加载顺序成为隐藏语义；
- 单位、范围和权限无法静态验证；
- 拼写错误只能运行时发现；
- 规则可以绕过唯一写入者；
- 缓存键会被无关字典内容污染；
- 以后很难区分硬约束、软约束和提示。

### 3.2 方案 B：立即提供脚本或插件运行时

做法：

- 规则包执行脚本；
- 脚本直接调用生成 API 或修改字段。

拒绝原因：

- 超出第一阶段安全边界；
- native/WASM 行为和浮点确定性难以统一；
- 需要权限、资源预算、沙箱和版本协议；
- 会在领域接缝尚未稳定时固化过宽 API；
- 与用户已确认的“不执行第三方任意代码”冲突。

### 3.3 方案 C：编译内能力注册表 + 数据化贡献 + 强类型解析

做法：

- 核心代码注册有限、版本化能力；
- 规则包只提交能力允许的受控数据；
- 世界法则包可以选择受信任核心模型；
- 普通规则包只能提交公开允许的贡献；
- 作者约束使用同一强类型目标，但保留独立来源；
- 解析器负责依赖、权限、冲突和归并；
- 生成阶段只消费解析后的最小输入。

选择此方案。

它以较窄的首个能力证明完整边界，同时保留以后增加自然强迫、生态和社会能力的正交扩展点。

## 4. 模块所有权与依赖方向

```text
world
  └─ natural contracts
          ▲
          │
rules ────┘
  ├─ ids / versions
  ├─ capability registry
  ├─ manifests / pack set
  ├─ author constraints
  ├─ tectonic constraint resolver
  └─ builtin earthlike pack
          ▲
          │
generators::natural::rule_input
  ├─ external artifacts
  ├─ resolution stage
  └─ minimal projection stage
          │
          ▼
generators::natural::tectonics
          │
          ▼
world::natural snapshots

app
  └─ only composes validated inputs and reads summaries
```

约束：

- `world` 不依赖 `rules`、`engine`、生成器、UI 或显示；
- `rules` 只依赖 `world` 与纯数据/哈希库；
- `rules` 不依赖 `engine`、生成器、app、egui、wgpu、旧 terrain；
- `generators::natural::rule_input` 是规则到引擎的薄适配层；
- `TectonicStage` 只依赖空间与最小已解析构造输入；
- app 不实现规则归并算法；
- 显示系统不回写规则或世界真值。

## 5. 稳定标识与版本

### 5.1 ID

新增三种私有字段、构造验证的稳定 ID：

- `RulePackId`：例如 `sekai.builtin.earthlike`；
- `CapabilityId`：命名空间、名称、非零版本；
- `RuleItemId`：规则包内部约束项，例如 `prefer-moderate-activity`。

标识采用现有稳定标识语法：

- 1..=128 ASCII 字节；
- 仅小写字母、数字、`.`, `-`, `_`；
- 首尾必须是字母或数字。

所有 ID：

- 实现 `Eq`, `Ord`, `Hash`；
- 反序列化时重新验证；
- 不接受保留版本 0；
- 不从加载顺序派生。

### 5.2 语义版本

`RuleVersion` 保存非零 major、minor 和 patch。

`RuleVersionRequirement` 表示：

- 必须 major 相同；
- 实际版本必须不小于声明的 minimum minor/patch；
- 第一阶段不支持范围表达式、预发布标签或构建标签。

这足以表达核心兼容性，同时避免实现一套不完整的通用 semver 解析器。

### 5.3 核心 schema 兼容范围

每个规则包声明包含当前 `WORLD_SPEC_SCHEMA_V1` 的闭区间。

范围必须：

- 两端非零；
- `min <= max`；
- 包含当前核心 schema，否则规则集解析失败。

## 6. 能力模型

### 6.1 能力描述

`CapabilityDescriptor` 声明：

- `CapabilityId`；
- `CapabilityCardinality`；
- 最低规则包权限；
- 是否允许作者直接提交贡献。

首个注册表包含：

1. `sekai.core.natural.tectonic-model@1`
   - `UniqueRequired`
   - 仅 `WorldLaw`
   - 作者不可提供
2. `sekai.core.natural.tectonic-controls@1`
   - `Merge`
   - `Ordinary` 或 `WorldLaw`
   - 作者可以提交

### 6.2 基数

- `UniqueRequired`：解析后的规则集中必须恰好一个提供者；
- `UniqueOptional`：允许 0 或 1 个提供者，保留给以后；
- `Merge`：允许多个提供者，由能力自己的归并器处理。

不使用一个通用“最后写入获胜”的覆盖器。

### 6.3 权限

`RulePackKind`：

- `Ordinary`
- `WorldLaw`

权限是最低门槛：

- 世界法则包可以提供普通能力；
- 普通规则包不能提供世界法则能力；
- 作者贡献由能力描述单独允许；
- 权限错误在生成前失败。

### 6.4 贡献类型

第一阶段贡献是封闭枚举：

- `TectonicModel(CurrentSliceV1)`
- `TectonicConstraint(RuleTectonicConstraint)`

每个变体能够返回唯一的 `CapabilityId`。规则包的 `provides` 由实际贡献派生并保存在清单中，避免“清单声称提供但没有数据”或“偷偷提交未声明能力”。

新增能力必须：

- 增加显式负载类型；
- 注册能力描述；
- 定义验证和归并器；
- 增加权限、冲突与确定性测试。

不允许任意 JSON、`Any`、未验证字节块或函数字段。

## 7. 规则包清单与内容哈希

### 7.1 `RulePackManifest`

保存：

- schema 版本；
- `RulePackId`；
- `RuleVersion`；
- `RulePackKind`；
- 核心 schema 兼容范围；
- 排序且唯一的规则包依赖；
- 排序且唯一的能力提供列表；
- 排序且唯一的能力消费列表；
- `RuleContentHash`。

### 7.2 内容哈希

`RulePack::new` 对不包含 hash 自身的稳定内容帧做 JSON 流式 BLAKE3：

- ID、版本、权限与兼容范围；
- 依赖与能力消费；
- 排序后的贡献。

构造器计算并写入 hash。反序列化时重新计算并拒绝不匹配值。

这不是安全签名；它是确定性内容身份。签名与来源认证属于以后存储/包管理切片。

### 7.3 安全预算

V1 上限：

- 最多 64 个活动规则包；
- 每包最多 32 个规则包依赖；
- 每包最多 32 个能力消费；
- 每包最多 256 个贡献；
- 规则集最多 4096 个贡献；
- 作者约束最多 4096 个。

超限在分配或求解前失败。

## 8. 规则集解析

### 8.1 结构验证

`RulePackSet` 构造时：

- 按 `RulePackId` 排序；
- 拒绝重复包 ID；
- 验证每包内容哈希；
- 验证集合预算。

反序列化必须走同一构造器。

### 8.2 依赖解析

解析时：

1. 验证每个依赖存在；
2. 验证版本满足要求；
3. 验证无自依赖；
4. 用稳定 Kahn 排序构造拓扑序；
5. 同时可选节点按 `RulePackId` 排序；
6. 若剩余节点非空，返回包含稳定最小循环成员的错误。

输入 Vec 顺序不影响拓扑序、hash 或结果。

### 8.3 能力解析

按内置注册表验证：

- 未知能力；
- 不支持版本；
- 权限不足；
- 缺失消费能力；
- 唯一能力无提供者；
- 唯一能力多提供者。

错误保存具体规则包和能力 ID。能力冲突不会降级为警告。

### 8.4 内置类地球规则包

`sekai.builtin.earthlike@1.0.0`：

- 类型：`WorldLaw`
- 核心 schema：V1
- 提供：`tectonic-model@1`
- 贡献：`CurrentSliceV1`
- 无网络、脚本或外部文件；
- 不提交构造控制约束，因此默认自然结果不变。

默认规则集只包含该包。

## 9. 作者约束与规则约束

### 9.1 强度

`ConstraintStrength`：

- `Hard`
- `Soft { weight }`
- `Hint { weight }`

权重：

- 使用 `u16`；
- 有效范围 1..=1000；
- 不使用浮点权重；
- 硬约束没有权重。

### 9.2 构造控制目标

`TectonicConstraintClause` 是封闭枚举：

- `PlateCount(InclusiveU16Range)`
- `ContinentalCrustPermille(InclusiveU16Range)`
- `Activity(ActivitySet)`

范围必须：

- 非空且正序；
- 位于 `TectonicSpec` 的安全边界；
- 大陆壳比例用千分数表达，避免规则归并中的浮点比较；
- 活动集合非空、排序且唯一。

规则约束和作者约束共享相同 clause 与强度，但来源不同。

### 9.3 来源

`ConstraintSource`：

- `RulePack { pack_id, item_id }`
- `Author(AuthorObjectId)`

规则包内 item ID 必须唯一。作者约束 ID 在集合内必须唯一。

来源参与：

- 稳定排序；
- 冲突错误；
- 采用记录；
- 诊断上下文。

### 9.4 作者约束集合

`AuthorConstraints`：

- 有 schema 版本；
- 只保存启用的有效约束；
- 按 `AuthorObjectId` 排序；
- 拒绝重复 ID；
- 反序列化重新验证；
- 空集合是合法默认值。

本切片不实现 UI 编辑。app 使用空作者约束输入，但正式阶段图和测试使用同一产物。

## 10. 确定性构造控制求解

### 10.1 候选域

三个目标使用有限候选域：

- 板块数：`MIN_PLATE_COUNT..=MAX_PLATE_COUNT`
- 大陆壳比例：`MIN..=MAX` 的整数千分数
- 构造活动：`Quiet`, `Moderate`, `Active`

如果某目标没有任何约束，原始 `TectonicSpec` 值逐位保留，不进行量化。

### 10.2 硬约束

每个候选必须满足全部硬约束。

若没有候选：

- 返回 `HardConstraintConflict`；
- 包含目标；
- 包含参与该目标的所有硬约束来源，稳定排序且去重；
- 不发布规则解析产物；
- 不运行下游构造或地貌阶段。

### 10.3 软约束与提示

对通过硬约束的每个候选计算：

1. `soft_penalty`
2. `hint_penalty`
3. `base_distance`
4. 稳定候选值

按以上四元组字典序选择最小值。

每条约束的 penalty：

- 候选在允许范围/集合内时为 0；
- 否则为到最近允许值的整数距离乘权重；
- 所有运算使用检查过的 `u64`；
- 软约束优先级始终高于提示；
- 提示只在软约束同分时影响结果；
- 原始 spec 只在约束同分时保持作者/UI 的当前偏好；
- 最后用稳定候选值打破完全同分。

这明确区分：

- Hard：可行域；
- Soft：主要权衡；
- Hint：风格性次级选择。

### 10.4 比例转换

大陆壳比例候选用千分数求解，最终通过 `permille / 1000.0` 写入 `f32` spec。

如果没有比例约束，保留原始 `f32`；有约束时输出是明确的千分数值。输出仍通过 `TectonicSpec::validate`。

### 10.5 采用记录

`ConstraintAdoption` 保存：

- 来源；
- 强度；
- 目标；
- `Satisfied` 或 `Compromised`。

硬约束只能是 `Satisfied`。软约束或提示如果最终值不在允许集合中，记录为 `Compromised`。

`TectonicRuleResolution` 保存：

- schema 版本；
- 已解析规则包身份、版本和内容 hash；
- 稳定依赖顺序；
- 选中的构造模型；
- 最终 `TectonicSpec`；
- 稳定排序的采用记录。

它是审计产物，不是自然权威字段。

## 11. 阶段与缓存边界

### 11.1 外部输入

自然基础图新增：

- `RulePackSetArtifact`
- `AuthorConstraintsArtifact`

保留：

- `PlanarSpaceArtifact`
- `TectonicSpecArtifact`

`TectonicSpecArtifact` 明确表示基础偏好输入，不再被 `TectonicStage` 直接读取。

### 11.2 规则解析阶段

`RuleTectonicResolutionStage`：

- 输入：基础构造 spec、规则集、作者约束；
- 输出：`TectonicRuleResolutionArtifact`；
- 负责规则集解析、权限、冲突、归并和采用记录；
- 失败时使用规则专属稳定错误码。

### 11.3 最小投影阶段

`ResolvedTectonicInputStage`：

- 输入：完整规则解析产物；
- 输出：`ResolvedTectonicInputArtifact`；
- 只保存构造模型与最终 `TectonicSpec`；
- 不保存规则包版本、hash、采用记录或诊断。

这是必要的缓存投影，不是无意义包装：

```text
规则审计变化
  → 规则解析重跑
  → 投影阶段重跑
  → 如果 model/spec 未变，投影 hash 未变
  → tectonics 与 relief 命中缓存
```

如果让 `TectonicStage` 直接依赖完整审计产物，增加一个结果相同的说明性规则就会错误地重建整个自然世界。

### 11.4 自然阶段

`TectonicStage` 改为只消费：

- `SpatialArtifact`
- `ResolvedTectonicInputArtifact`

它：

- 根据受信任模型枚举选择编译内实现；
- V1 只支持 `CurrentSliceV1`；
- 不知道规则包 ID、作者 ID、约束强度或 UI。

`ReliefStage` 无需改变依赖。

### 11.5 失败原子性

- 规则解析失败不发布半成品产物；
- BuildEngine 返回完整失败报告；
- app 继续显示上一份有效自然文档和渲染包；
- 规则输入失败不得清空画布。

## 12. 应用接入

默认 app：

- 每次候选构建创建内置能力注册表和默认规则集；
- 提供空作者约束；
- 保持现有板块数量、大陆比例、活动控件作为基础 spec；
- 成功构建后显示只读摘要：
  - 活动规则包数；
  - 作者约束数；
  - 采用/妥协约束数；
- 不在本切片提供规则或约束编辑器；
- 失败时摘要与地图一同原子保留。

应用持久化状态不保存内置包的展开副本，以免程序升级后继续使用过时的内置清单。未来项目存储切片将保存规则包选择与内容身份。

## 13. 错误分类

### 13.1 构造错误

- 非法 ID、版本或 schema 范围；
- 内容 hash 不匹配；
- 集合或单包预算超限；
- 重复 pack、依赖、能力消费或规则项；
- 非法约束范围、活动集合或权重；
- 重复作者对象 ID。

### 13.2 解析错误

- 缺失依赖；
- 不兼容依赖版本；
- 依赖循环；
- 未知能力；
- 权限不足；
- 缺失消费能力；
- 唯一能力缺失或冲突；
- 硬约束冲突；
- 评分溢出；
- 最终 spec 验证失败。

错误必须：

- 有稳定枚举变体；
- 包含可定位 ID；
- 通过 stage adapter 转换为稳定机器码；
- 不用 warning 代替不变量失败。

## 14. 确定性与安全

- 所有公开集合在构造时排序和去重；
- 所有解析遍历使用 `Vec`、`BTreeMap` 或 `BTreeSet`；
- 不使用 `HashMap` 迭代决定结果；
- 不读取系统时间、环境随机数或全局 RNG；
- 规则解析不消费 `StageRng`；
- 增加无效果规则不能改变自然随机流；
- 规则内容 hash 使用稳定序列化；
- 规则数据有数量和数值上限；
- 不执行规则包代码；
- 不访问文件、网络、UI 或 GPU；
- native 与 WASM 使用同一纯数据算法。

### 15.1 标识、版本与清单

- 缺失依赖；
- 不兼容版本；
- 自依赖和循环；
- 稳定拓扑序；
- 未知能力；
- 权限不足；
- 缺失消费；
- 唯一能力缺失/冲突；
- 多个 merge 提供者；

### 15.3 约束

- 合法和非法范围；
- 非法权重；
- 活动集合归一化；
- 规则项和作者 ID 重复；
- Hard 交集；
- Hard 冲突及稳定来源；
- Soft 优先于 Hint；
- Hint 只打破 Soft 同分；
- base 只做后备偏好；
- 完全同分稳定打破；

- 比例量化只在被约束时发生；
- 采用/妥协记录正确；
- 规则包输入顺序不改变结果。

### 15.4 阶段与缓存

- 外部产物键和 schema 稳定；
- 阶段依赖精确；
- 默认规则解析选择 `CurrentSliceV1`；
- 默认解析输出原始 spec；
- 硬冲突在自然生成前失败；
- 规则审计变化但投影相同时，tectonics/relief 命中缓存；
- 投影改变时，tectonics/relief 失效；
- 规则集 hash 和根种子随机流正交；
- 相同输入产物 hash 一致。

### 15.5 应用与回归

- app 提供全部新增外部产物；
- 默认路径不绕过解析阶段；
- 失败保留上次地图、包和摘要；
- 现有自然 golden 逐字节不变；
- native、release、Clippy、fmt、wasm 和 Trunk 全部通过。

## 17. 自审

### 17.1 正交性

- 规则契约不依赖引擎或 UI：通过。
- 引擎适配集中在生成器输入阶段：通过。
- 自然算法只读最小解析输入：通过。
- 审计产物与生成缓存键通过投影分离：通过。
- 规则不能写最终字段：通过。

### 17.2 单一职责

- registry 负责能力定义；
- manifest/pack set 负责身份、内容和依赖；
- constraints 负责强类型作者/规则输入；
- resolver 负责权限、冲突和确定性归并；
- stage adapter 负责 Artifact/Stage；
- TectonicStage 继续只负责生成构造快照。

通过。

### 17.3 非空壳

- 唯一构造模型能力真实决定生成实现；
- 构造控制能力真实改变已解析 `TectonicSpec`；
- 默认内置包是正式应用必需输入；
- 作者约束通过正式阶段图可运行；
- 未实现的热量、水分、魔法等能力没有占位类型。

通过。

### 17.4 安全与确定性

- 无脚本、网络、时间或全局 RNG；
- 稳定排序、固定点权重、有限候选域；
- 内容 hash 可重算；
- 数量与数值有界；
- 冲突构建失败且可定位；
- native/WASM 共用代码。

通过。

### 17.5 未来扩展

以后增加一个新能力时，不需要修改现有能力归并器：

1. 定义强类型贡献；
2. 注册能力描述；
3. 实现独立 resolver；
4. 用独立审计产物和最小投影连接负责阶段。

魔法地理、气候强迫、作者地形编辑和社会偏好都可以复用这一模式，而不获得直接写字段的权限。
