# Sekai 构造自然基础 V1 设计

**状态：** 自审通过，进入实施计划  
**日期：** 2026-07-29  
**上位设计：** `docs/superpowers/specs/2026-07-28-sekai-current-slice-world-design.md`  
**问题来源：** 独立字段显示接入真实旧地形后，默认地图暴露出由椭圆大陆掩膜主导的宏观形状。

## 1. 摘要

本切片建立 Sekai 正式自然生成链的第一段：

```text
SpatialSnapshot
  + TectonicSpec
  → 板块、地壳、相对运动与构造边界段
  → 地壳基准、构造地貌、区域起伏与浮点高程
  → 类型化字段只读接入独立显示系统
```

它用有限平面上的一次性构造事件合成替换默认应用中的椭圆大陆主链，不执行地质历史积分，也不生成历史事件。

V1 交付的是可独立验证的自然基础，不是假装完整的 `NaturalSnapshot`。水文、侵蚀、气候、岩性、土壤、生态和资源仍属于后续自然子切片。

## 2. 已确认的问题

当前默认地形并不是“显示成了椭圆”，而是旧生成器先创建 1–4 个 `ContinentEllipse`，再让板块种子在大陆或海洋掩膜内扩张。随后高程主要取决于该掩膜的海岸距离和随机内陆山峰。

因此：

- 显示系统忠实呈现了生成结果；
- 给椭圆边缘增加更多噪声只能遮盖根因；
- 继续扩展旧 `PlateLayer` 会让错误的数据所有权固化；
- 正确修复必须从正式世界契约、阶段产物和因果顺序入手。

## 3. 方案比较与决策

### 3.1 方案 A：修饰旧椭圆掩膜

做法是增加扭曲噪声、更多椭圆、岛屿图元和后处理。

优点：

- 改动小；
- 很快能得到不那么规则的轮廓。

缺点：

- 大陆仍先于板块与地壳存在；
- 板块运动仍不是地形主因；
- 继续依赖 egui 坐标、旧数组和 `u8` 高程；
- 作者约束和后续自然阶段没有稳定接入点。

**结论：不采用。**

### 3.2 方案 B：完整板块时间模拟

做法是持续积分板块运动、碰撞、裂解、洋壳年龄和地壳变形。

优点：

- 可以表达长期地质演化；
- 物理叙事完整。

缺点：

- 超出有限平面当前切片的范围；
- 计算、收敛、参数校准和作者控制成本过高；
- 会提前引入当前明确排除的历史时间模型。

**结论：不采用。**

### 3.3 方案 C：正式的一次性构造事件合成

做法是先生成独立的板块分区和地壳状态，再从相邻板块的相对运动产生边界事件，最后把均衡基准和有界事件场合成为当前高程。

优点：

- 符合已确认的自然因果顺序；
- 不需要时间积分；
- 板块、地壳、地貌和显示职责分离；
- 能保留所有重要中间字段并独立验证；
- 作者约束和规则能力以后可以通过类型化输入接入。

**结论：采用。**

研究方向与本项目既定设计一致：程序化构造方法可以用板块相对运动和近似的碰撞、俯冲、扩张等过程生成大尺度地貌，而不必运行昂贵的完整物理模拟。参考：

- [Procedural Tectonic Planets](https://doi.org/10.1111/cgf.13614)
- [Azgaar/Fantasy-Map-Generator 的数据、生成、编辑和渲染分层](https://github.com/Azgaar/Fantasy-Map-Generator)

Sekai 不复刻这些实现；它们只用于核对因果方向和职责边界。

## 4. 范围

### 4.1 包含

- 强类型 `PlateId` 和 `BoundarySegmentId`；
- 语义化、可校验的 `TectonicSpec`；
- 板块种子、连通板块分区和板块速度；
- 与板块独立生成的大陆壳/海洋壳和地壳厚度；
- 相邻板块非共动约束；
- 逐内部边计算相对运动；
- 汇聚、俯冲、离散、走滑和弱边界分类；
- 连续同类边的确定性边界段聚合；
- 地壳均衡/大陆边缘基准；
- 构造事件场、区域起伏和最终 `f32` 米制高程；
- 统一海平面基准和海陆分类；
- 正式生成阶段、产物、验证、缓存与诊断；
- 核心字段到 `FieldView` 的借用式接入；
- 默认应用切换到正式自然基础；
- 固定种子的契约、性质、集成、性能和视觉验收。

### 4.2 不包含

- 地质年代、板块时间积分、事件时间线；
- 完整球面、周期边界或地图投影；
- 水文、侵蚀、沉积、气候、冰川；
- 岩性、热点、土壤、生态和资源；
- 魔法自然强迫；
- 通用规则包、作者约束 UI 或地图编辑；
- 完整 `NaturalSnapshot` 或 `WorldSnapshot`；
- 网络、河流和矢量箭头的 GPU 叠加；
- 旧地形模板的迁移或重写。

## 5. 架构边界

### 5.1 模块所有权

```text
world::natural
  只拥有类型、单位、规格、不可变快照和验证
          ↑
generators::natural
  只拥有板块/地壳/边界/地貌算法和生成阶段
          ↑
app
  只负责编排构建、保留最后有效结果并接入显示
          ↓
view → gpu / ui
  只读取字段和几何，不调用生成算法
```

约束：

- `world::natural` 不导入 engine、generators、terrain、models、view、egui、eframe 或 wgpu；
- `generators::natural` 不导入 app、ui、gpu、egui、eframe 或旧 `terrain`；
- `view` 不导入 generators 或 app；
- `app` 是唯一允许同时接触构建产物、字段显示状态和 GPU 资源的组合根；
- 新主链不读取 `ContinentEllipse`、`TerrainTemplate`、`CellsData.height` 或旧 `MapSystem` 几何；
- 旧 `terrain` 保持可编译，直到所有消费者迁移后再单独删除。

### 5.2 阶段拆分

#### `TectonicStage`

唯一职责：从空间拓扑和构造规格生成当前构造基底。

输入：

- `SpatialArtifact`
- `TectonicSpecArtifact`
- 本阶段独立随机流

权威输出：

- `TectonicArtifact`

它不生成高程，不访问显示设置，也不解释颜色。

#### `ReliefStage`

唯一职责：把地壳状态与构造边界事件解释为当前固体表面。

输入：

- `SpatialArtifact`
- `TectonicArtifact`
- 本阶段独立随机流

权威输出：

- `ReliefArtifact`

它不修改板块或地壳，不执行侵蚀、气候或水文。

#### `natural_foundation_graph`

固定图：

```text
PlanarSpaceArtifact ─→ SpatialStage ───────────────┐
                                                   ├→ TectonicStage → ReliefStage
TectonicSpecArtifact ──────────────────────────────┘
```

空间、构造和地貌拥有不同的阶段 ID、版本、随机流和缓存键。

### 5.3 规则与作者约束接缝

规则能力子系统尚未实现时，构造阶段只消费外部的类型化 `TectonicSpecArtifact`。它不得直接读取 UI 状态或任意参数字典。

以后：

- 世界法则包可以选择受信任的构造模型和合法参数；
- 普通规则包和作者输入可以提交板块种子、运动、地壳或边界约束；
- 组合层把这些输入归并成经过校验的构造输入产物；
- `TectonicStage` 的输出契约和下游消费者不需要改变。

V1 不创建空壳规则 API，也不把临时 UI 控件伪装成约束系统。

## 6. 领域契约

### 6.1 ID 与单位

新增：

- `PlateId(u32)`：单次构造快照中连续、稳定的板块身份；
- `BoundarySegmentId(u32)`：按最小成员边排序后分配的稳定边界段身份；
- `PlateVelocity`：每年毫米的二维定点速度；
- `CrustThickness`：千米单位的有限 `f32`；
- `ElevationField`：米单位的有限 `f32` 密集字段。

板块速度使用整数毫米/年作为权威值：

- 分类和非共动约束不依赖平台浮点细节；
- 显示时可派生为厘米/年的 `Vector2F32`；
- V1 有效范围为每轴 `-120..=120 mm/year`。

### 6.2 `TectonicSpec`

只暴露语义参数，不暴露 Dijkstra 权重、噪声频率或平滑轮数等算法旋钮：

```rust
pub struct TectonicSpec {
    pub schema_version: u16,
    pub plate_count: u16,
    pub continental_crust_fraction: f32,
    pub activity: TectonicActivity,
}
```

V1 范围：

- `plate_count: 2..=64`，并且不能超过单元数允许的安全上限；
- `continental_crust_fraction: 0.10..=0.75`；
- `activity: Quiet | Moderate | Active`；
- schema 版本必须受支持。

默认类地球配置：

- 12 个板块；
- 38% 大陆壳；
- `Moderate` 构造活动。

大陆壳比例不是最终陆地比例。海平面、地壳厚度、构造抬升和区域起伏共同决定陆地。

### 6.3 板块与地壳

```rust
pub struct Plate {
    pub id: PlateId,
    pub seed_cell: CellId,
    pub velocity: PlateVelocity,
}

pub enum CrustKind {
    Oceanic,
    Continental,
}
```

`TectonicSnapshot` 保存：

- schema 版本；
- 单元和边基数；
- 连续、按 ID 排序的板块表；
- 每单元板块 ID；
- 每单元地壳类型；
- 每单元地壳厚度；
- 每边构造分类、强度和可选边界段 ID；
- 按 ID 排序的边界段；
- 构建算法版本需要的稳定元数据。

板块与地壳是两个权威字段：

- 地壳生成不读取板块 ID；
- 改变板块数量不得改变固定根种子下的地壳随机子流；
- 一块板块允许同时承载大陆壳和海洋壳；
- 一片大陆壳允许跨越多个板块。

### 6.4 边界事件

每条空间内部边都有一个边对齐的 `BoundaryKind`：

```text
None
Weak
ContinentalCollision
Subduction
ContinentalRift
OceanicRidge
Transform
```

规则：

- 同板块内部边只能是 `None`；
- 不同板块的内部边必须有非 `None` 分类；
- 外边界不是板块碰撞边界；
- `Subduction` 保存确定性的俯冲侧；
- 强度有限且归一化到 `0..=1`；
- 每条跨板块边恰好属于一个边界段。

`BoundarySegment` 保存：

- 稳定 ID；
- 有序板块对；
- 事件类型；
- 排序且非空的成员 `EdgeId`；
- 平均强度；
- 可选俯冲板块；
- 段级方向摘要。

边界段是当前构造事实，不带年份、持续时间或历史序列。

### 6.5 `ReliefSnapshot`

保存以下边对齐/单元对齐的可解释分量：

- `crust_base_elevation_m`：地壳均衡与大陆边缘基准；
- `tectonic_offset_m`：边界事件 stamping 的净贡献；
- `regional_offset_m`：拓扑平滑的区域起伏；
- `elevation_m`：三个分量的和，经过统一安全范围处理；
- `land_ocean_kind`：相对统一海平面的派生分类；
- `sea_level_m`：V1 全局统一基准，默认 `0 m`。

恒等式在允许的舍入容差内成立：

```text
elevation_m =
    crust_base_elevation_m
    + tectonic_offset_m
    + regional_offset_m
```

V1 高程范围：

- `-11_000..=9_000 m`；
- 所有值必须有限；
- 分类前量化到厘米，避免微小浮点差异改变海陆类别；
- `u8` 只允许在导出或兼容适配器中派生。

## 7. 确定性生成算法

### 7.1 随机子流

每个阶段从调度器获得一个独立 `StageRng`。构造阶段立即抽取固定长度的根材料，再按稳定标签派生子流：

```text
plate-seeds
plate-motion
crust-seeds
crust-shape
```

算法分支和板块数量不能通过“多消费几次 RNG”污染无关子系统。地貌阶段同样为区域起伏和事件细节使用不同标签。

禁止进程全局 RNG、系统时间和非确定性集合迭代。

### 7.2 公共量化图

生成器从 `SpatialSnapshot` 构建只读的内部 `NaturalTopologyIndex`：

- 稳定单元邻接；
- `(CellId, CellId) → EdgeId`；
- 量化共享边长度；
- 量化单元中心；
- 外边界单元；
- 单元面积权重。

物理长度按地图最大尺度量化为正整数。构造分类、最短路优先级和所有并列决策只使用整数与稳定 ID。

该索引是算法缓存，不进入世界真值或序列化格式。

### 7.3 板块种子

1. 从独立子流选择首个有效单元；
2. 后续种子使用量化世界距离的 farthest-point 采样；
3. 随机值只用于稳定并列打破和候选旋转；
4. 每个种子必须唯一。

这样避免板块种子扎堆，同时不把规则网格、Delaunay 索引或 egui 坐标泄漏进算法。

### 7.4 连通板块分区

从所有板块种子运行一次多源 Dijkstra：

- 边权为物理长度与稳定、板块无关的边扰动之积；
- 队列顺序为 `(累计代价, PlateId, CellId)`；
- 每个单元只接受严格更优或按稳定 ID 更小的并列来源；
- 每个板块区域由自己的种子沿图扩张，因此保持连通；
- 输出不是椭圆掩膜，也不依赖大陆壳。

边扰动改变生长路径和边界曲折度，但不会制造负权、断裂板块或像素级随机孤岛。

### 7.5 独立地壳场

地壳不是板块类型。

1. 从 `crust-seeds` 子流选择大陆壳核和海洋壳核；
2. 海洋核对有限平面外缘有软偏好，但不是硬边框；
3. 两组种子分别在使用 `crust-shape` 权重的图上计算距离；
4. 每个单元得到“接近大陆核”与“接近海洋核”的整数差分分数；
5. 按 `(分数, CellId)` 稳定排序，并按量化单元面积选取目标大陆壳比例；
6. 距离地壳过渡边界越远，大陆壳越厚；洋壳保持较薄；
7. 小幅区域变化由图平滑随机场提供，不直接改变地壳类别。

结果可以形成大陆、半岛、海湾、陆桥和碎片，不使用椭圆、径向大陆模板或先验海岸线。

### 7.6 非共动板块速度

板块邻接图从分区结果派生。速度从固定整数候选晶格选择：

1. 按 `PlateId` 顺序处理；
2. 用 `plate-motion` 子流旋转候选检查起点；
3. 对每个候选计算它与已赋值相邻板块的最小相对速度平方；
4. 选择最大化该最小值的候选；
5. 活动级别决定候选速度范围和最小相对速度；
6. 最终验证所有相邻板块满足非共动下限。

如果合法规格仍无法满足约束，阶段失败，不把大量静止边界静默发布为有效结果。

### 7.7 逐边分类

对每条跨板块内部边：

1. 使用两侧单元量化中心得到局部法向；
2. 计算板块相对速度的法向与切向整数投影；
3. 相对速度过低时为 `Weak`；
4. 法向占优且靠近时为汇聚；
5. 法向占优且远离时为离散；
6. 切向占优时为 `Transform`；
7. 汇聚结合两侧地壳类型与厚度区分大陆碰撞和俯冲；
8. 离散结合地壳类型区分大陆裂谷和洋中脊。

分类不使用高程，因此不存在“先看山脉再反推碰撞”的循环依赖。

### 7.8 边界段聚合

使用确定性并查集聚合边界边。两条边只有在以下条件同时满足时才能合并：

- 共享量化端点；
- 有相同有序板块对；
- 有相同边界类型；
- 俯冲极性一致；
- 无向边方向满足固定夹角阈值。

每个集合按最小 `EdgeId` 排序，随后分配连续 `BoundarySegmentId`。成员边和段列表都保持稳定排序。

### 7.9 地壳基准与大陆边缘

地貌阶段从地壳类型、厚度和距地壳过渡边界的图距离生成基准：

- 大陆壳内部形成较高、较宽的稳定基底；
- 大陆边缘向海平面附近过渡；
- 海洋壳内部形成深洋盆；
- 洋壳边缘形成大陆坡和陆架过渡；
- 所有宽度以世界米制尺度定义，并相对地图较短边设置安全上下限。

这一步不读取板块速度；其唯一原因是地壳状态和统一海平面。

### 7.10 构造事件 stamping

边界段首先产生单元侧的效果源：

| 边界 | 主要效果 |
|---|---|
| 大陆碰撞 | 两侧宽褶皱抬升 |
| 俯冲 | 俯冲侧窄海沟、覆盖侧偏移火山弧/山带 |
| 大陆裂谷 | 负地形裂谷及较弱肩部抬升 |
| 洋中脊 | 宽海底脊抬升 |
| 走滑 | 窄、低幅的正负断层地貌 |
| 弱边界 | 不产生或只产生诊断级微弱贡献 |

每种效果使用一次有最大传播距离的多源图最短路，不按“每段 × 全图”暴力扫描。紧支撑平滑核把距离、段强度和单元侧角色转换为米制贡献。

事件场只描述形成当前地貌的算法，不保存事件发生时间。

### 7.11 区域起伏

区域起伏使用拓扑图上的确定性多尺度扩散：

1. 为每单元生成稳定零均值原始值；
2. 分别进行固定次数的邻域平滑；
3. 组合宽、中、细三个尺度；
4. 大陆与海洋使用不同幅值；
5. 最终场保持近似零均值并限制幅度。

它补充区域高原、盆地和不规则海底，不决定大陆壳类别，也不能覆盖构造事件的主因地位。

### 7.12 高程与海陆

三个分量相加后：

1. 校验有限值；
2. 超出安全范围时有界钳制并发出结构化诊断；
3. 量化到厘米后与唯一海平面比较；
4. 生成 `Land` / `Ocean`；
5. 保留原始 `f32` 米制高程，不归一化为 `u8`。

## 8. 字段与显示接入

### 8.1 借用式核心字段

现有 `FieldView` 只能借用拥有 `Vec` 的 `FieldData`。为避免把全部核心自然字段复制到 `ExtensionFieldSet`，V1 增加只读负载引用：

```rust
pub enum FieldPayloadRef<'a> {
    ScalarF32(&'a [f32]),
    CategoryU32(&'a [u32]),
    Boolean(&'a Vec<bool>),
    Vector2F32(&'a [[f32; 2]]),
    StableIdU32 { target: StableIdKind, values: &'a [u32] },
}
```

`FieldView::from_payload` 校验 schema 与引用类型。`FieldCatalog::from_payloads`：

- 以 registry 顺序建立目录；
- 拒绝未知或重复字段；
- 允许已注册但当前没有负载的字段；
- 不拥有或复制字段数组。

原有 `ExtensionFieldSet` 构造器继续工作，并通过同一引用枚举实现。

### 8.2 正式自然字段

注册表至少暴露：

| 字段 ID | 域 | 类型 | 单位 | 主要依赖 |
|---|---|---|---|---|
| `sekai.core.natural.plate_id@1` | Cells | CategoryU32 | — | — |
| `sekai.core.natural.crust_kind@1` | Cells | CategoryU32 | — | — |
| `sekai.core.natural.crust_thickness_km@1` | Cells | ScalarF32 | km | crust kind |
| `sekai.core.natural.plate_velocity@1` | Cells | Vector2F32 | cm/year | plate id |
| `sekai.core.natural.boundary_kind@1` | Edges | CategoryU32 | — | plate id, velocity, crust |
| `sekai.core.natural.boundary_strength@1` | Edges | ScalarF32 | — | boundary kind |
| `sekai.core.natural.crust_base_elevation_m@1` | Cells | ScalarF32 | m | crust, thickness |
| `sekai.core.natural.tectonic_offset_m@1` | Cells | ScalarF32 | m | boundary fields |
| `sekai.core.natural.regional_offset_m@1` | Cells | ScalarF32 | m | — |
| `sekai.core.natural.elevation_m@1` | Cells | ScalarF32 | m | three elevation components |
| `sekai.core.natural.land_ocean@1` | Cells | CategoryU32 | — | elevation |

字段 ID、单位、有效范围、缺失策略、依赖和显示元数据全部固定并经过注册表验证。

单元速度可以由板块表和每单元板块 ID 在显示文档中派生一次；它是可丢弃的显示缓存，不是第二份权威速度。

### 8.3 应用组合

新增 `NaturalFieldDocument`，拥有：

- 构建成功后的 `Arc<SpatialArtifact>`；
- `Arc<TectonicArtifact>`；
- `Arc<ReliefArtifact>`；
- 正式字段注册表；
- 一次构建的 `PreparedCellMesh`；
- 从 `BuildReport` 转换的只读显示诊断；
- 少量明确标记的派生显示缓存。

应用流程：

```text
编辑种子或语义构造规格
  → 构建完整候选产物
  → 验证候选自然字段与显示包
  → 成功：原子替换当前文档与 GPU 包
  → 失败：保留上一份完整地图并展示错误
```

默认选择 `elevation_m`，并使用以海平面为语义中心的发散调色板。高程的权威有效范围仍为
`-11_000..=9_000 m`；默认显示使用围绕 `0 m` 的对称手动范围，不能为了调色板中心而修改或
截断权威值。

### 8.4 画布与旧主链

正式空间范围使用真实米制默认值，不能把 `2000 × 1000` 当作米制世界。

应用默认：

- 宽 `20_000 km`；
- 高 `10_000 km`；
- 约 `20_000` 个空间单元；
- 首次发布新网格时自动 fit-to-view；
- 画布缩放下限支持世界米制范围。

旧 Delaunay、Voronoi、点和旧高度填色不再参与默认组合。旧模块仍保留编译和测试，但应用不会把两套不相同的几何叠在一起。

## 9. 验证与错误策略

### 9.1 `TectonicSnapshot` 不变量

- schema 版本受支持；
- 单元、边和字段长度一致；
- 板块 ID 从 0 连续，板块表按 ID 排序；
- 每个板块拥有自己的种子；
- 每个板块区域连通；
- 每个单元引用有效板块；
- 地壳类型合法；
- 大陆壳与海洋壳厚度分别处于物理安全范围；
- 所有速度处于范围内；
- 相邻板块满足非共动下限；
- 同板块边为 `None`；
- 跨板块边为非 `None`；
- 边界强度有限且在 `0..=1`；
- 边界段无空段、无重复成员且恰好分割全部跨板块边。

需要空间语义的检查由 `validate_against(&SpatialSnapshot)` 执行。产物自身的 `Artifact::validate` 执行不依赖外部对象的内部检查。

### 9.2 `ReliefSnapshot` 不变量

- 所有单元字段长度一致；
- 所有分量和高程有限；
- 每个值处于声明范围；
- 分量恒等式在固定容差内成立；
- 海陆分类与厘米量化后的海平面比较一致；
- 默认类地球配置同时产生海洋和陆地。

### 9.3 失败与诊断

致命错误：

- 非法规格；
- 拓扑与产物基数不匹配；
- 无法选择足够唯一种子；
- 无法满足非共动约束；
- 非有限或越界权威值；
- 边界段覆盖错误；
- 字段 schema 或负载不匹配。

非致命诊断：

- 极少数高程被安全钳制；
- 默认配置的陆地比例偏离宽松质量区间；
- 某一主要边界类型在给定小板块图中未出现。

任何致命错误都阻止候选地图发布。应用继续显示上一份完整结果。

## 10. 测试策略

### 10.1 契约测试

- ID、单位和规格的 serde 往返；
- 非有限、越界和未知 schema 拒绝；
- 快照自身验证与 `validate_against`；
- 字段 schema、依赖、单位和范围；
- 借用式 `FieldPayloadRef` 不复制源数组；
- 旧 `ExtensionFieldSet` 目录行为保持兼容。

### 10.2 确定性测试

- 相同根种子、规格和空间产物得到相同序列化字节与内容哈希；
- 不同根种子改变板块、地壳或区域起伏；
- 改变板块数量不改变独立地壳子流的固定夹具结果；
- 稳定集合顺序和并列规则不依赖 `HashMap`；
- 固定小夹具断言精确板块、地壳、边界和海陆分类。

### 10.3 性质测试

对多组固定种子验证：

- 所有板块非空且连通；
- 所有跨板块边被分类并恰好属于一个段；
- 所有相邻板块非共动；
- 至少在默认质量种子集中出现承载两类地壳的板块；
- 至少在默认质量种子集中出现跨多个板块的大陆壳区；
- 实际大陆壳面积接近目标比例；
- 默认高程同时含海洋与陆地；
- 高程范围、有限性和分量恒等式成立。

“板块和地壳独立”是结构不变量；不要求每一个极端随机种子都必须产生某种特定地图构图。

### 10.4 算法回归

- 新 `generators::natural` 不引用 `ContinentEllipse`、旧 `terrain` 或 egui；
- 默认固定种子的大陆壳边界包含多个连通段、凹入和跨板块关系；
- 不把板块 ID 当作地壳类型；
- 不从最终高程反推边界类型；
- 不产生无成员边界段或重复边。

### 10.5 阶段与缓存

- 图具有精确阶段顺序和依赖；
- 改变显示状态不改变构建哈希；
- 改变构造规格只失效构造及下游，不失效空间阶段；
- 改变根种子失效全部随机阶段；
- 重复构建命中缓存且语义哈希相同；
- 失败构建不暴露半成品产物。

### 10.6 显示与视觉验收

- 正式快照几何可直接构建完整显示网格；
- 每个可填色字段的单元数与网格一致；
- 边字段和向量字段可检查但不会错误启用 V1 单元填色；
- 固定种子的板块、地壳和高程 CPU 参考图保存为 golden；
- GPU 离屏输出与 CPU 参考一致；
- 实际应用默认打开高程视图且自动适配窗口；
- 手工/截图检查确认：
  - 不再出现由少量椭圆直接构成的大陆；
  - 板块与大陆边界不重合；
  - 山带、海沟/海脊方向与构造边界一致；
  - 没有空白洞、NaN 颜色或几何错位；
  - 切换字段不会重新生成世界。

视觉验收不是用“看起来有噪声”替代契约测试；两者都必须通过。

### 10.7 性能与平台

默认 20,000 单元目标：

- 空间 + 构造 + 地貌的 release 构建在开发机上记录实测时间；
- 构造算法额外内存保持 `O(cells + edges + plates)`；
- 固定数量的多源传播，不执行 `segments × cells`；
- 不在 UI 每帧重建网格或字段；
- native、release、Clippy、rustfmt、wasm check 和 Trunk build 全部通过。

性能门槛先记录可重复基线，不用未经多机测量的毫秒数制造虚假硬指标。若默认构建影响交互，再基于 profile 单独制定优化切片。

## 11. 默认视觉质量门

固定验收种子不只检查“不是椭圆”，还检查因果可读性：

1. 板块视图有稳定、连通、大小合理的非椭圆分区；
2. 地壳视图形成多个不规则大陆壳区和海洋壳区；
3. 至少一条大陆壳区跨过板块边界；
4. 至少一个板块同时包含两类地壳；
5. 汇聚边界附近出现正地貌，俯冲侧可出现负地貌；
6. 离散洋壳边界附近出现海底脊；
7. 区域起伏打破大面积完全平坦，但不掩盖构造主形态；
8. 高程视图具有可辨认海洋、大陆、山带和盆地；
9. 海岸线没有由 1–4 个椭圆直接拼接的可见特征。

如果契约正确但固定验收图仍显著呈规则椭圆或无因果地噪声化，本切片不算完成。

## 12. 迁移与删除边界

本切片完成后：

- 默认应用使用正式空间、构造和地貌产物；
- 旧模板生成器仍作为未迁移兼容代码存在；
- `CellsData.height` 不再是默认显示真值；
- 旧渲染叠加不再与正式几何混用；
- 后续自然阶段只消费正式 `SpatialArtifact`、`TectonicArtifact` 和 `ReliefArtifact`。

以下删除必须留到单独清理切片：

- 旧模板 UI；
- 旧 `TerrainGenerator` 主链；
- `CellsData.height: Vec<u8>`；
- 旧 MapSystem 的重复三角剖分与填色适配；
- 不再有消费者的旧 GPU/空间资源。

延后物理删除可以降低一次提交的回归范围，但不得继续让旧产物进入正式因果链。
