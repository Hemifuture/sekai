## 1. 摘要

Sekai 第一阶段建设一个面向世界观作者的中世纪奇幻世界生成、解释与编辑工具。系统输出自然、魔法和社会彼此一致的**当前世界切片**，不模拟或展示历史时间线。

地质构造、侵蚀、文化扩散、人口竞争和政体扩张等过程可以作为形成当前状态的算法，但它们不产生虚构年份、君主、战争或编年事件。系统用字段依赖和主要影响因素解释当前结果，而不是伪造历史叙事。

总体架构采用**强类型核心 + 模式化扩展注册表**：

- 拓扑、自然环境、魔法基础、人口、聚落和政体使用稳定强类型契约；
- 规则包通过带 schema、单位、依赖和版本的字段、约束与作用量扩展世界；
- 生成引擎、领域模型、显示、存储和外部集成保持单向依赖；
- 第一阶段不执行第三方脚本、动态库或任意代码。

本设计是完整产品蓝图，不是单次实现计划。实施必须拆成可独立验收的子系统，每个子系统分别经过设计、计划、测试和交付。

## 2. 已确认的产品决策

### 2.1 目标体验

- 默认规则集保持中世纪和幻想感，不进入工业化。
- 世界默认遵循类地球自然规律，关闭魔法后仍可完整生成。
- 首个完整纵切同时包含自然、魔法和社会，而不是只生成地形。
- 作者能够查看所有重要中间字段，并理解城市、文化区、政体边界等结果的主要形成原因。
- 作者输入通过约束、作用量和规则参数进入因果链，不直接涂改内部数组。

### 2.2 第一阶段包含

- 平面世界的空间拓扑、尺度、边界条件和确定性种子；
- 板块、地壳、构造边界、高程、海陆、海底和岩性；
- 水文、侵蚀、沉积、气候、土壤、生态和自然资源；
- 魔力场、源汇、屏障、节点、地脉、异常区和传送连接；
- 非人智慧物种、人口、文化、聚落、路线、贸易潜力、政体和当前边界；
- 字段级依赖与重要实体的轻量因素说明；
- 独立字段显示、诊断显示、项目保存和可复现重建；
- 聚落到外部城市或村庄布局生成器的确定性链接。

### 2.3 第一阶段明确排除

- 历史年份、时代推进、编年史和事件时间线；
- 王朝、战争经过、人物生平和历史回放；
- 实时持续运行的世界沙盒；
- 球面 Goldberg 网格和完整球面板块运动；
- 第三方脚本、动态插件和不受信任代码执行；
- 城市内部街道、建筑几何及其回写；
- 多人协作、云同步和网络服务；
- 规则包直接访问 UI、GPU、任意内存或内部数组。

未来历史系统必须作为独立设计接入。第一阶段不预建空的事件框架，也不为尚未批准的时间模型污染核心类型。

## 3. 架构原则

### 3.1 正交性与单一职责

每个模块必须拥有一个清晰职责、最小输入和权威输出。领域之间通过数据契约通信，不直接调用彼此的内部算法。

每个模块都必须回答：

1. 它唯一负责什么；
2. 它消费哪些稳定输入；
3. 它产生哪些权威输出；
4. 它能否在不修改消费者的情况下替换内部算法；
5. 它能否使用固定输入独立测试。

若两个模块需要互相调用，应视为边界设计失败。解决方式是提取共同契约、调整数据所有权，或把真正不可分割的迭代封装为一个有界联合求解阶段。

### 3.2 数据真值与派生物分离

- `WorldSnapshot` 是完成构建后的世界真值。
- GPU 缓冲区、颜色、三角形展开数据和 UI 状态都是显示派生物。
- 求解器临时缓存和性能索引是可重建构建产物。
- 项目输入与作者约束是可编辑源数据。
- 不得为了渲染或缓存方便复制另一套互相漂移的领域真值。

### 3.3 确定性优先

相同项目输入、根种子、算法版本和规则包版本必须产生等价结果。生成顺序、线程调度和是否打开某个显示图层不得影响世界。

### 3.4 适度抽象

只有存在两个真实实现或明确替换边界时才定义 trait。普通领域算法优先使用具体类型；禁止创建万能上下文、万能实体、万能字段或任意 hook。

## 4. 系统边界

```text
ProjectManifest
WorldSpec
AuthorConstraints
RulePackSet
IntegrationPreferences
        │
        ▼
┌─────────────────────────────┐
│         World Engine        │
│ graph / scheduler / cache   │
│ invalidation / diagnostics  │
│ provenance                  │
└──────────────┬──────────────┘
               │
               ▼
        Immutable WorldSnapshot
          │                 │
          ▼                 ▼
       Field View         Storage
          │
          ▼
       egui / wgpu

SettlementLayoutHints
          │
          ▼
SettlementLayoutProvider
          │
          ▼
External city/village generator URL
```

### 4.1 顶层模块

- `world`：稳定领域类型、单位、ID、拓扑接口、字段 schema 和快照。
- `engine`：生成依赖图、调度、缓存、失效传播、确定性随机、诊断和因果摘要。
- `rules`：内置中世纪奇幻规则、规则包 schema、能力和作用量。
- `view`：把快照暴露为标量、分类、向量、网络和实体视图。
- `storage`：项目清单、schema 迁移、快照缓存和导入导出。
- `integrations`：外部城镇布局等非核心适配器。
- `app`：egui 编辑器和流程编排，不承载领域真值。

### 4.2 依赖方向

- `world` 不依赖其他业务模块。
- `engine` 和 `rules` 依赖 `world`。
- `view` 只依赖 `world` 提供的快照与视图契约。
- `storage` 依赖公开序列化 schema，不访问生成器内部状态。
- `integrations` 消费公开领域数据，不被领域模块反向依赖。
- `app` 可以编排其余模块，其余模块不得依赖 `app`。

第一阶段维持一个 Rust package，通过模块可见性执行边界。只有接口稳定、确实存在独立编译或复用需求时才拆成多个 crate。

## 5. 核心数据契约

### 5.1 输入、构建和输出

- `ProjectManifest`：项目格式版本、规则包集合、集成偏好和构建引用。
- `WorldSpec`：空间范围、拓扑、尺度、根种子、中世纪技术配置和全局规则。
- `AuthorConstraints`：作者明确指定的硬约束、软约束和提示。
- `RulePackSet`：已选择规则包、解析后的版本、依赖和能力提供关系。
- `IntegrationPreferences`：外部布局 provider 等不改变世界真值的项目级集成选择。
- `WorldDraft`：仅在引擎内部存在的受控构建状态。
- `BuildArtifacts`：阶段缓存、临时索引和可选诊断字段。
- `WorldSnapshot`：不可变的当前世界切片。
- `BuildReport`：错误、警告、约束采用情况、阶段耗时和内容哈希。

UI、显示和普通规则包不能获得可修改的 `WorldDraft`。

### 5.2 `WorldSnapshot` 组成

- `SnapshotHeader`：schema、算法与规则版本、种子、输入哈希和构建信息。
- `SpatialSnapshot`：单元、边、邻接、面积、中心、距离、边界条件和空间索引描述。
- `NaturalSnapshot`：地壳、板块、高程、水体、气候、土壤、生态和资源。
- `MagicSnapshot`：魔力场、源汇、屏障、节点、地脉、异常区和特殊连接。
- `SocietySnapshot`：物种、人口群体、文化、聚落、路线、贸易关系、政体和边界。
- `ExtensionFields`：通过 schema 注册的规则包字段。
- `ProvenanceIndex`：字段依赖和重要实体的因素分解。

快照不包含年份序列、事件列表或可变运行状态。

`SnapshotHeader` 中参与世界身份的构建信息只能包含稳定版本和目标信息。墙钟时间、阶段耗时、线程数和机器信息只进入 `BuildReport`，不得参与语义内容哈希。

### 5.3 ID、单位与范围

- 使用 `CellId`、`EdgeId`、`SpeciesId`、`CultureId`、`SettlementId`、`PolityId` 等强类型 ID。
- ID 在单次快照中稳定，不能把裸数组下标跨模块当作公共身份。
- 相同输入与算法版本重建时，空间和生成实体 ID 必须稳定；算法版本改变后不承诺自动保持生成实体身份。
- 需要跨重建保存的作者对象使用独立项目级 ID。持久约束优先引用世界坐标、语义区域或作者对象 ID，不引用易变化的单元数组位置。
- 引用生成实体的持久约束同时保存可诊断锚点；目标消失时约束进入“未解析”状态，不静默绑定到另一个实体。
- 高程、距离、温度、降水、流量、面积和人口等使用有明确语义的类型或新类型。
- 每个连续字段声明单位、有效范围、缺失值策略和数值精度。
- `u8` 高程只能作为显示或导出结果，不能作为自然系统的权威高程。

### 5.4 空间拓扑

领域算法通过语义接口读取：

- 单元邻接；
- 单元面积和中心；
- 共享边及边长；
- 位置、距离和方向；
- 边界条件；
- 区域与网络查询。

算法不得依赖 egui 坐标、Delaunay 内部索引布局或特定 Voronoi 几何。当前抖动网格、Delaunay 和 Voronoi 实现通过适配器接入。

首个实现是有限平面矩形；周期平面和球面不是第一阶段能力。

### 5.5 扩展字段注册表

核心字段使用强类型存储。扩展字段必须注册：

- 命名空间与稳定字段 ID；
- schema 版本；
- 值类型；
- 空间域或实体域；
- 单位与有效范围；
- 缺失值策略；
- 依赖字段；
- 显示元数据；
- 序列化兼容规则。

首阶段允许的 `FieldData` 是受控集合：标量、整数分类、布尔、二维向量和稳定 ID 引用。禁止把任意对象或无 schema 的字节块放入核心字段注册表。

核心与扩展字段都通过零拷贝或借用式 `FieldView` 暴露给显示系统，不为了通用显示复制整份数据。

## 6. 生成引擎

### 6.1 阶段契约

每个生成阶段声明：

- 稳定阶段 ID 和算法版本；
- 最小类型化输入；
- 权威输出；
- 规则能力需求；
- 随机流命名空间；
- 全局或局部失效能力；
- 验证器；
- 可选诊断输出。

阶段只能读取声明的输入，并返回自己的输出。阶段不能持有完整可变世界，也不能通过全局单例交换隐藏状态。

每个核心字段只有一个权威写入阶段。其他模块若要影响它，必须提交该阶段公开支持的约束或作用量。

### 6.2 当前切片管线

```text
世界规则与作者约束
  → 空间拓扑与尺度
  → 板块、地壳与构造边界
  → 原初魔法源与自然强迫
  → 高程、海陆、海底与岩性
  → 初步气候
  → 水文、侵蚀与沉积
  → 最终气候、积雪与冰川
  → 土壤、生态、资源与魔法生态
  → 物种适生性与人口承载力
  → 文化区与人口分布
  → 聚落选址
  → 道路、航路、传送网络与贸易潜力
  → 聚落规模与人口平衡
  → 政体扩张、边界与当前关系
  → 聚落布局提示
  → 派生地图、因果摘要与快照验证
```

这些步骤生成形成式当前状态：

- 侵蚀改变地貌，但不记录某年的洪水；
- 文化通过空间扩散形成当前分区，但不编造迁徙年代；
- 政体通过人口、可达性、资源和阻力竞争形成当前边界，但不编造战争；
- 当前贸易和外交压力可以保存，产生它们的历史事件不保存。

### 6.3 有界联合求解

必须互相反馈的过程封装为单个有界求解阶段，例如：

- 初步气候、侵蚀和最终气候；
- 聚落、路线、贸易潜力和聚落规模；
- 人口承载力、生态压力和魔法适应。

联合求解器必须定义最大迭代数、收敛指标、未收敛诊断和稳定输出策略。调度图本身保持无环，禁止隐藏迭代依赖。

### 6.4 确定性随机

根种子按阶段 ID、规则包命名空间和稳定实体 ID 派生独立随机流：

```text
stage_seed = hash(root_seed, stage_id, stage_version, namespace)
entity_seed = hash(stage_seed, stable_entity_id)
```

不得使用进程全局 RNG。增删无关阶段不能改变既有阶段的随机序列。拓扑点集也必须使用派生种子。

### 6.5 缓存与失效

阶段缓存键包含：

- 阶段 ID 与算法版本；
- 输入内容哈希；
- 相关规则包版本；
- 相关约束哈希；
- 派生随机种子。

第一批实现允许整阶段失效。`DirtyRegion` 是显式能力，只有证明局部结果与全局不变量一致的阶段才能声明支持局部重算。

正确性优先于局部重算速度。局部能力不能通过“只更新数组的一部分”伪装实现。

### 6.6 因果摘要

默认记录字段级依赖图。重要实体额外保存有限数量的主要因素：

```text
城市 A
  河流可达性        +0.31
  可耕地            +0.24
  区域贸易中心性    +0.19
  魔法危险          -0.18
```

因素使用稳定原因 ID、来源引用、带符号权重和本地化说明键。它不是完整计算轨迹，也不宣称时间上的因果事件。

## 7. 规则包、魔法与作者输入

### 7.1 规则包清单

`RulePackManifest` 声明：

- 稳定 ID 和语义版本；
- 兼容的核心 schema 与能力版本；
- 规则包依赖；
- 提供和消费的能力；
- 注册字段和参数 schema；
- 内容哈希。

加载顺序不能决定语义。依赖图显式排序；缺失依赖、循环依赖、重复唯一能力和不兼容版本均在构建前失败。

### 7.2 两级权限

普通规则包可以：

- 定义物种、生态、资源、文化原型和魔法内容；
- 注册扩展字段；
- 提交公开的约束、作用量和评分修正；
- 提供显示元数据和名称数据。

普通规则包不能：

- 替换核心存储；
- 写入未声明字段；
- 绕过调度器；
- 访问网络、系统时间、UI 或 GPU；
- 执行任意脚本。

世界法则包可以配置或选择受信任的核心能力，如重力、天体、昼夜、热量来源和空间规则。第一阶段所有能力实现编译进应用；数据包只能在明确允许的模型与参数中选择。

### 7.3 作用量归并

- 可叠加物理量使用声明的归并器，例如热量强迫求和。
- 唯一能力只能有一个提供者。
- 分类替换必须由该能力明确允许。
- 不使用通用“加载优先级覆盖一切”的规则。
- 冲突必须产生可定位到规则包与字段的错误。

### 7.4 魔法语义

魔法通过以下公开能力影响世界：

- 地形变形和局部重力；
- 热量、水分、风和渗透性；
- 生态压力、适应和资源富集；
- 移动成本、屏障和传送边；
- 人口健康、生产力、聚落吸引力和文化倾向。

魔法不能直接写最终颜色、任意高度数组或政体边界。

神祇在第一阶段是信仰对象、规则来源或魔法作用域，不是具有历史时间线的自主行动者。

### 7.5 物种与文化

非人智慧物种是一等领域实体。物种定义生物性约束，如寿命、生育、体型、环境适应、感知和魔法亲和。

文化不从属于物种。多个物种可以共享文化，同一物种可以形成多个文化。社会算法消费物种与文化的组合，不硬编码人类逻辑。

### 7.6 作者约束

- `HardConstraint`：必须满足；无法满足时构建失败并解释冲突。
- `SoftConstraint`：参与评分与权衡。
- `Hint`：只引导风格和随机选择。

作者在 UI 中“修改结果”时，系统创建约束或覆盖来源，并从负责该字段的阶段开始失效下游。最终字段标记自动生成、作者指定或规则包贡献的来源。

## 8. 社会当前切片

### 8.1 社会生成范围

社会层生成：

- 物种适生性和人口承载力；
- 人口群体及其空间分布；
- 文化、语言和信仰的当前分区；
- 聚落位置、类型、等级、人口和功能；
- 道路、航路、传送连接和贸易潜力；
- 政体、行政区域、边界和当前关系压力。

社会层不生成君主谱系、建城年份、战争经过或文化迁徙事件。

### 8.2 聚落职责

`Settlement` 保存世界尺度事实：

- 稳定 ID、位置和占用空间；
- 名称、人口和等级；
- 物种与文化组成；
- 所属政体；
- 港口、交通、经济与资源角色；
- 环境和魔法特征；
- 形成因素摘要。

Sekai 不在第一阶段生成城市内部街道和建筑。

### 8.3 外部城镇布局

系统采用与 Azgaar 相同的 link-out 职责分离思路：

- `SettlementLayoutHints` 从聚落事实派生布局种子、城市或村庄类别、规模、城墙、河流、海岸、道路和地形提示；
- 布局种子由世界种子和 `SettlementId` 派生；
- `SettlementLayoutProvider` 把标准提示转换为外部生成器链接；
- 默认适配 Watabou City Generator 和 Village Generator；
- 小型聚落使用村庄布局，大型聚落使用城市布局；
- 提供者选择存于项目集成偏好，不是世界自然或社会真值；
- URL 在点击时生成，不作为唯一持久化数据；
- URL 只能由受信任 provider 适配器根据类型化参数生成，规则包不能注入任意跳转地址；
- 打开外部页面必须由用户显式触发；
- 外部服务不可用只产生非致命集成错误，不影响世界快照；
- 第一阶段不导入外部布局结果。

未来本地城镇生成器只需实现同一 provider 契约，不修改社会生成模块。

## 9. 显示与作者交互

### 9.1 独立显示模块

显示系统只消费 `WorldSnapshot`、`BuildReport` 和显式诊断字段。它不得调用生成算法，也不得把颜色写回世界。

支持的视图：

- 连续标量：高程、温度、降水、流量、人口和魔力密度；
- 分类字段：板块、地壳、岩性、生态、文化和政体；
- 向量字段：板块速度、风和洋流；
- 网络：河流、道路、航路、地脉和传送连接；
- 点与区域：城市、资源点、异常区和行政区；
- 诊断：无效值、缺失值、来源、依赖、脏区域和约束冲突；
- 因素说明：选择实体后展示主要正负因素。

字段调色板、显示范围和模式优先通过 GPU uniform 与稳定字段缓冲完成。静态几何和字段仅在内容变化时上传，禁止每帧在 CPU 重建全部颜色与 Voronoi 三角形。

### 9.2 编辑命令

UI 操作转换为显式命令：

```text
用户操作
  → 校验编辑命令
  → 修改 WorldSpec / AuthorConstraints / RulePackSet
  → 计算失效范围
  → 重建
  → 原子替换有效快照
```

撤销和重做作用于项目输入命令，不作用于任意世界数组。

## 10. 存储与版本

### 10.1 逻辑项目内容

项目必须保存：

- 项目格式版本；
- `WorldSpec`；
- 作者约束；
- 规则包 ID、版本和内容哈希；
- 集成偏好；
- 可选的最近有效快照；
- 可选的阶段缓存；
- 构建报告摘要。

项目输入是权威源。快照和缓存可被删除并重新构建。

### 10.2 格式原则

- 清单、规则参数和约束采用显式、可迁移的结构化 schema。
- 大型密集字段可以使用带类型头、长度、校验和与压缩信息的二进制块。
- 不序列化 Rust 内存布局、trait object、GPU 缓冲或线程状态。
- 每次迁移保留原始文件，失败时不覆盖用户项目。
- 未知普通扩展字段在 schema 可识别时保留；不兼容核心 schema 时拒绝静默加载。

物理容器由存储子系统规范决定，但逻辑格式对原生文件系统和浏览器下载/上传一致。

## 11. 错误、诊断与安全

错误按边界分类：

- 项目与规格验证错误；
- 拓扑和字段不变量错误；
- 规则包依赖或能力冲突；
- 阶段执行或不收敛；
- 快照验证失败；
- 存储与迁移失败；
- 外部集成失败。

规则：

- 任一权威阶段失败时不发布半成品快照；
- 应用继续展示上一份有效快照；
- 错误包含阶段、字段、规则包、约束和空间范围等结构化上下文；
- 警告不能代替违反不变量的错误；
- 外部城镇链接失败是非致命错误；
- 规则数据设置尺寸、数量、迭代和数值范围上限；
- 第一阶段不执行不受信任代码。

## 12. 确定性与跨平台

- 同一目标平台、算法版本和输入要求字节级稳定。
- 原生与 WASM 的稳定 ID、拓扑、分类结果和实体关系必须一致。
- 连续浮点字段允许明确记录的数值容差，但所有影响分类与实体生成的阈值使用稳定排序、确定性归并和必要的规范化量化，避免微小浮点差异放大为不同世界。
- 并行算法不得依赖非确定迭代顺序或非确定浮点归并。
- 快照头记录目标、算法和数值兼容版本。

## 13. 测试策略

### 13.1 单元与契约测试

- ID、单位、字段 schema 和序列化往返；
- 拓扑邻接、边共享、面积和距离不变量；
- 阶段输入最小化与唯一字段写入；
- 规则包依赖、冲突和权限；
- 约束采用、冲突和来源标记；
- 聚落布局提示与链接生成。

### 13.2 属性与不变量测试

- 高程、水量、温度和人口值域；
- 河网有向无环与汇流守恒；
- 海陆、水体和海岸一致；
- 聚落位于允许区域；
- 政体区域引用有效；
- 所有实体 ID 和引用有效；
- 扩展字段长度、域和 schema 一致。

### 13.3 确定性测试

- 相同种子重复构建得到相同哈希；
- 打开或关闭显示图层不改变快照；
- 增加无关规则字段不改变既有随机流；
- 原生与 WASM 固定夹具满足跨平台契约。

### 13.4 集成与黄金测试

- 固定小型拓扑运行完整阶段图；
- 每个子系统提供人工可验证夹具；
- 固定种子保存字段统计、实体关系和截图基线；
- CPU 参考采样与 GPU 输出抽查；
- 极值、NaN、缺失值和非法分类值使用醒目诊断颜色。

### 13.5 性能回归

- 跟踪阶段耗时、峰值内存、缓存命中和 GPU 上传字节；
- 静态画面不得每帧重建世界字段或几何；
- 性能优化不得改变确定性和不变量。

## 14. 从当前代码迁移

采用渐进替换而不是一次性重写：

1. 修复现有 CI 门禁，并记录当前测试和截图基线。
2. 在现有 package 中建立新模块边界、强类型 ID、单位、`WorldSpec` 和最小快照。
3. 把现有 Grid/Delaunay/Voronoi 包装为确定性的 `SpatialSnapshot` 适配器。
4. 建立阶段图、派生随机流、诊断、缓存键和快照验证。
5. 先用固定夹具实现独立字段显示，再接真实生成字段。
6. 让旧地形生成器通过兼容适配器输出新高程字段，保持应用可运行。
7. 按新规范逐步替换地质、地形、水文、气候、魔法和社会阶段。
8. 所有消费者迁移后删除旧 `CellsData.height: Vec<u8>` 主链、重复三角剖分和每帧 CPU 重建路径。

可复用部分包括经过测试的 Delaunay/Voronoi、空间索引、画布交互和部分 GPU 基础设施。现有分层地形与模板逻辑只能作为算法参考或兼容输入，不能定义新领域契约。

## 15. 子系统拆分与交付顺序

总体设计必须拆为以下独立规范和实施计划：

1. **世界基础与生成引擎**
   - ID、单位、规格、拓扑适配、字段契约、快照、阶段图、随机流、诊断和验证。
   - 交付可构建并保存的最小夹具快照。

2. **独立字段显示**
   - 通用字段视图、GPU 标量/分类显示、网络与实体叠加、诊断模式和截图测试。
   - 只使用夹具快照即可验收。

3. **规则能力与作者约束**
   - 规则清单、注册表、普通/世界法则权限、作用量、约束和中世纪奇幻内置配置。
   - 使用示例规则包证明隔离、冲突诊断和确定性。

4. **自然世界生成**
   - 地质、地形、水文、侵蚀、气候、土壤、生态和资源。
   - 输出完整自然快照与字段验证。

5. **魔法地理**
   - 魔力源汇、传播、地脉、异常、传送边及其自然作用。
   - 关闭规则包时自然世界保持完整。

6. **社会当前切片**
   - 物种、人口、文化、聚落、路线、贸易潜力、政体、边界和因素说明。
   - 不包含历史事件。

7. **作者工具、存储与外部集成**
   - 编辑命令、撤销重做、失效重建、项目迁移、导出和城镇布局链接。

每个子系统都必须独立通过设计评审、TDD 实施计划、契约测试和集成验收。不得编写一个覆盖全部系统的巨型实施计划。

## 16. 第一阶段总体验收

第一阶段完成时必须满足：

- 固定种子能生成自然、魔法和社会完整当前切片；
- 关闭魔法仍能生成自洽类地球世界；
- 中世纪奇幻规则不产生工业化社会特征；
- 重要字段具有单位、范围、来源、版本和依赖；
- 城市、文化区和政体边界可显示主要形成因素；
- 作者约束通过重建进入结果，不直接修改真值数组；
- 所有重要中间字段可独立显示和诊断；
- 聚落可以打开确定性外部城市或村庄布局链接；
- 原生与 WASM 满足确定性契约；
- 项目输入可以保存、迁移并重新构建；
- UI、生成、规则、显示和存储不存在反向业务依赖；
- 不包含历史时间线、事件生成或回放功能。
