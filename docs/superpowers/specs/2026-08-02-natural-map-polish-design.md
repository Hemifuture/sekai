# Sekai 自然地图可信度修正设计

日期：2026-08-02  
状态：已批准实施

## 1. 背景

当前 `Continents` 已能稳定产生多个大陆和封闭地图海洋边框，但实际应用截图暴露了三个相邻问题：

1. 多个大陆之间出现等宽、连续、Y 形的深海缝。它们来自 Relief 阶段按大陆分量重建 Voronoi 分隔骨架，并把骨架单元强制压低，而不是来自地壳或板块运动。
2. 字段面板直接显示 `field.sekai...` 本地化键，分类图例也显示键值，普通作者无法快速理解字段。
3. 板块边界分类已经使用相对速度法向投影，但边界强度仍取总相对速度；斜向运动会夸大碰撞或裂谷强度。构造地貌沿长边界的幅度也过于一致。

这些问题都属于已批准的当前时间切片：本切片已经拥有板块、构造地貌、高程、水文和侵蚀，不需要也不得等待历史时间线系统。

## 2. 目标

- 多大陆默认图中，大陆由有宽度、有深度梯度且轮廓不规则的海洋盆地隔开，不出现人为固定深度骨架。
- 世界形态预设继续只影响地壳空间形态，不改变板块种子、分区或速度随机流。
- Relief 只解释地壳、边界、地幔和自身确定性随机流，不重建或修补预设的大陆分量意图。
- 字段列表、分类图例、域、类型、范围模式和调色板控件显示简体中文；稳定 `FieldId` 与本地化键保持不变并在检查器中可见。
- 汇聚/离散强度由相对速度法向分量决定，走滑强度由切向分量决定。
- 构造地貌加入有空间相关性的确定性幅度变化，保留事件符号、构造类型和可复现性。
- 保持现有阶段依赖、字段所有权、封闭边界海洋、精确大陆地壳比例和性能界限。

## 3. 非目标

- 不做板块时间积分、碰撞后的速度反馈、地质年代或历史事件。
- 不实现球面欧拉极板块旋转或东西周期接缝。
- 不把噪声加入边界类型判断，也不从最终高程反推边界类型。
- 不建立通用多语言框架或运行时语言切换；本切片只提供一个 UI 层简体中文目录和稳定回退。
- 不改变公开快照字段结构，不增加“预设分隔线”领域字段。

## 4. 方案比较

### 4.1 只删除 Relief 深海分隔线

优点是改动小；缺点是大陆可能再次由浅海或构造隆升焊接。它只删除症状保护，没有把分隔责任放回正确阶段，因此不采用。

### 4.2 在 Relief 中模糊现有分隔线

视觉会变软，但 Relief 仍需识别大陆分量并解释预设意图，继续违反单一职责；分隔线也仍然没有自然因果，因此不采用。

### 4.3 形成阶段保留自然海洋走廊，Relief 通用解释（采用）

地壳形成阶段围绕大陆核所有权分界保留宽度可变的海洋壳区。Relief 删除大陆分量分隔器，只通过地壳边缘距离形成大陆架、陆坡和深海渐变。宽走廊自身足以抵抗普通区域隆升和构造贡献，因此不需要后处理切槽。

字段中文化采用 UI 目录而不是修改 schema。构造可信度采用运动投影和有界相关扰动，而不是给最终高度撒白噪声。

## 5. 模块边界

### 5.1 `generators::natural::tectonics`

唯一新增职责是改善其已有的两项输出语义：地壳空间形态与边界强度。

- `generate_crust` 仍不读取 `PlateIdField`。
- 大陆核、地壳种类和厚度仍使用独立标签随机流。
- 板块生成函数和板块随机标签保持原样。
- 边界分类仍只读取板块速度、局部法向、地壳种类和厚度。

### 5.2 `generators::natural::relief`

- 删除 `apply_oceanic_component_separators` 及固定分隔深度。
- `synthesize_crust_base` 继续是地壳均衡和大陆边缘的唯一解释器。
- `synthesize_tectonic_offset` 消费边界记录及 Relief 专属细节随机流，生成带有相关变化的构造贡献。
- 封闭地图海洋边框仍是 Relief 的通用边界条件保护，不属于任何预设。

### 5.3 `ui::field`

- 新增一个具体的简体中文键解析模块。
- `world::fields` 继续只保存稳定本地化键，不依赖 UI 或具体语言。
- 未知扩展键原样回退，保证未来规则包字段仍可检查。
- 检查器保留 `namespace.name@version` 技术标识。

## 6. 海洋走廊算法

多核预设首先按现有方法得到最近大陆核所有权和所有权分界单元。随后从分界单元运行一次多源拓扑距离场，并在候选大陆评分前保留走廊。

每个预设的基础走廊半宽（按典型邻接步数）为：

| 预设 | 基础半宽 |
|---|---:|
| `Continents` | 2 |
| `Archipelago` | 1 |
| `Supercontinent` | 0，且不建立内部走廊 |
| `GreatIsland` | 2 |
| `VolcanicIslands` | 1 |

现有平滑形状噪声同时提供走廊宽度变化：噪声为正的单元在基础半宽上增加一步，其他单元使用基础半宽。由于噪声已经在拓扑图上扩散，这一变化形成连续宽窄段而不是逐格抖动。

选择目标大陆面积时，依次尝试最大走廊半宽、缩窄一级、仅保留所有权分界，最后才允许在极端作者大陆比例下取消走廊。推荐比例与质量种子必须始终通过最大或缩窄一级方案；不得依靠最后的取消走廊回退。

走廊只约束 `CrustKind::Oceanic`，不写高程。大陆比例仍以单元面积权重选择最接近目标的前缀，并保持一最大单元面积误差。

## 7. 通用海底地形

删除按大陆分量生成的深海骨架后，海洋地壳基准仍按距地壳过渡边界的距离，从大陆架邻域平滑趋向洋盆内部基准。宽走廊因此自然表现为：

```text
大陆边缘 → 大陆架/陆坡 → 海洋盆地 → 陆坡/大陆架 → 另一大陆
```

任何两个具有相同地壳种类、厚度和过渡距离的海洋单元都得到相同地壳基准；“最近大陆属于哪个分量”不再改变高程。构造海沟只能由俯冲边界产生。

## 8. 构造运动与地貌

对两侧速度 `v0`、`v1` 和局部法向 `n`：

```text
r = v1 - v0
normal_speed = abs(dot(r, n)) / length(n)
tangent_speed = sqrt(max(length(r)^2 - normal_speed^2, 0))
```

- 相对总速度低于弱边界阈值时仍为 `Weak`。
- 法向占优时，`dot(r, n) < 0` 为汇聚，`> 0` 为离散。
- 切向占优时为 `Transform`。
- 汇聚/离散的 `BoundaryRecord::strength` 使用 `normal_speed`。
- 走滑的强度使用 `tangent_speed`。
- 强度除以理论最大相对速度 `2 * sqrt(2) * MAX_PLATE_VELOCITY_MM_PER_YEAR` 并钳制到 `0..=1`。

这保证三块水平板块中，左右静止而中间向左时，左边界汇聚、右边界离散；中间板块额外的沿边界运动不会夸大两侧碰撞/裂谷强度。

Relief 增加标签为 `relief-tectonic-detail-v1` 的独立子流。原始值经过固定次数拓扑扩散后归一化，并把非零构造贡献乘以 `0.75..=1.25` 的相关系数。该步骤：

- 不改变零值或正负号；
- 不改变边界类型和俯冲极性；
- 相同输入、版本和种子完全复现；
- 不读取区域起伏随机流，新增细节不会因调用顺序影响其它字段。

## 10. 版本与兼容

- `TectonicStage` 从版本 2 提升到 3，使地壳走廊和边界强度语义正确失效缓存。
- `ReliefStage` 从版本 4 提升到 5，使删除分隔骨架和新增构造细节正确失效缓存。
- `TectonicSnapshot`、`ReliefSnapshot` 和字段 schema 结构不变，不提升快照 schema。
- UI 本地化不进入构建哈希，不改变世界产物。

## 11. 测试与验收

### 11.1 自动测试

- 固定多大陆质量种子中，不同主要大陆之间至少有多层海洋单元；推荐比例不能命中“取消走廊”回退。
- 大陆比例误差、预设分量轮廓、板块正交性和封闭边界海洋矩阵继续通过。
- 等地壳条件、等过渡距离的海洋单元不会因大陆分量归属得到特殊深槽。
- 三板块夹具验证左汇聚、右离散。
- 给板块相对速度增加纯切向分量，不改变其法向事件强度。
- 不同 Relief 种子改变沿线细节，相同种子字节级复现，且构造贡献不变号。
- 36 个正式自然字段均有中文标签；动态板块与河级键正确解析；未知键回退原文。
- UI 控件与检查器使用中文显示，同时保留稳定技术 ID。

### 11.2 视觉验收

在 Release 应用中至少检查 `Continents` 的以下视图：

- 地壳类型：主要大陆之间有实际海洋壳宽度，不贴边。
- 地壳基准高程：海峡/海盆具有渐变，不出现等宽固定深度 Y 形骨架。
- 构造地貌偏移：山带、裂谷和海沟与板块边界一致，沿线幅度不完全统一。
- 当前地表高程与地表水：多个大陆保持分离，侵蚀后无人工切槽或边缘陆地。
- 板块编号：切换预设不改变同版本同种子的板块状态。
- 左侧字段列表与分类图例：普通标签为中文，技术 ID 只在检查器中保留。

### 11.3 质量门

运行 Debug 与 Release 相关测试、全工作区测试、严格 Clippy、格式检查、WASM check、Trunk build、20,000 单元质量矩阵和性能门。更新所有受算法版本影响的正式 golden，并人工审阅而不是盲目接受。
