# Sekai 项目进度

更新时间：2026-11-01。本页顶部描述本地整合候选；下方早期记录仅作历史。

## 当前可运行候选

主目录使用 `integration/sekai-current`，已经汇合海岸 UI 修复、A9/校验去重/预热、
Phase A 作者配方闭环和站点气候导出。本轮未推送远端；本地 `main` 尚未因这些候选前移。

当前管线是球面拓扑 → 演化板块/地壳 → 基底与初级地形 → 起点气候 → 地表过程 →
终点气候与水文一致性验证 → 原子发布。程序化大陆是明确的初态先验，不只改变显示岸线。

已具备的工程能力：

- 两种重建按钮按本帧参数判断准入，恢复不支持的设置时也不启动错误生成。
- 细域海岸着色、实际安装批次拾取与河口同源；个别湖泊限制仍未解除。
- 进程内几何预热、工作区复用、构造边界验证一次与指纹去重。
- 作者输入事务、撤销重做、取消/晚到结果隔离、原子发布、配方保存和重开。
- 当前发布世界的站点取样/月表/足迹/导出；旧世界缓存随发布或清空项目失效。
- 气候未满足的建议范围在 UI 摘要中可见，读取生产质量报告，不另造阈值。

## 当前结论

Sekai 第一阶段仍然聚焦前工业、中世纪幻想世界的当前时间切片，不实现历史时间线。当前版本已经把世界基础、可观察显示和自然底座的主链贯通到：

```text
空间拓扑
  → 世界形成预设
  → 板块 / 地壳 / 当前边界运动
  → 地幔热点 / Relief / 地质
  → 初步气候
  → 水文 / 侵蚀
  → 当前地表与只读字段显示
```

这是一条可运行、可验证的自然生成纵切，不等于第一阶段全部完成。魔法、生态、社会、作者工具、存储和外部城镇生成器链接仍在后续范围内。

## 本次自然底座检查点

本次合并解决了海洋过于干净、只有大块陆地而缺少有成因小岛的问题，同时保持原有系统边界：

- 热点仍由 Mantle 唯一拥有；Relief 只在其正式正影响域内塑造海山与火山岛组。
- 洋—洋俯冲岛弧只读取 Tectonics 已分类的当前边界，并写入 `tectonic_offset_m`。
- `volcanic_offset_m` 只表达热点火山地貌；噪声不能脱离因果支撑独立造陆。
- 世界形成预设不改变板块 ID、归属、速度或边界分类，只把宏观初态传给后续阶段。
- 外边界与东西可见边框继续保持海洋；当前有限平面没有伪装成已经实现的无缝球面。
- 生成只解释当前切片，不新增年龄、事件、轨迹或时间轴。

## 主线发布验证

`13b8118` 合并后的 `main` 在推送前重新通过：

- README/进度页本地链接检查、`cargo fmt --all -- --check` 与 `git diff --check`；
- all-feature Check 与 `cargo clippy --all-targets --all-features -- -D warnings`；
- `cargo test --all-targets --all-features`：191 个库测试通过、1 个既有压力测试忽略，其他测试目标通过；
- release golden 和固定种子质量矩阵：2 个测试通过、1 个写入型 golden 更新测试按设计忽略；
- 20,000 单元 release 性能门：总耗时 `1801.849 ms`，Mantle `13.362 ms`，Relief `41.410 ms`；
- wasm32 all-feature library Check 与 `trunk build`。

本机 Windows 没有被 wgpu 标记为 fallback 的软件 GPU 适配器，因此设置 `SEKAI_REQUIRE_FIELD_GPU=1` 的 CI 专用强制模式会明确报告 `no fallback adapter is available`；普通本地测试按契约跳过该可选证据。该测试和请求 fallback 的逻辑自 `6f198b1` 起未被本次合并修改。强制 GPU/CPU 离屏一致性由安装 Mesa Vulkan 的 `field_display_gpu` CI job 提供，不以本机硬件渲染器替代软件参考证据。

## 后续方向

下一步应继续沿当前切片的依赖方向补齐自然世界，而不是启动历史模拟。进入新里程碑前，应从总体设计中选择一个边界清晰的专项切片，先确认其输入、权威输出和验收标准；优先候选是土壤—生态基础，或对当前气候/水文链的质量深化。具体选择尚未在本检查点承诺。
